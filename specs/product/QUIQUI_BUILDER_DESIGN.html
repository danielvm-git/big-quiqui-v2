Architecture proposal · QuiQui restart · Nov 2026

QuiQui Builder

One scene player, a small set of interaction primitives, and a template library that mirrors every TutoTOONS Builder template that real scenes use (30 of 44). QuiQui Care is the first game built on it. Later QuiQui titles reuse the same templates and add only art, voice and scene data.

Correction: the Builder has 44 templates, not 59. They are numbered 0–4 and 20–58, and numbers 5–19 do not exist. Each template keeps its TutoTOONS number in its QuiQui id, so the mapping stays traceable.

Scene-data pass done: I opened the scene files of the 13 Builder titles. 14 template numbers never appear in any scene, so they are empty slots and we do not build them. The 11 wave-1 templates cover 87% of template scenes. Three earlier guesses changed: the old "t42 rub" is really a slicing scene, the cleaning mechanic is t23 (erase) together with t40 (draw), and t20, not t47, is the main drag-to-target.

Everything is named in English: code, ids, data keys and file names. The game shows no text during play, so translating it means swapping voice files. See "English-first naming" below.

Diagram 1 · Layers

Five layers, one direction

Each layer only uses the layer below it. Templates never know which game they are in. Scene data never contains code. A new QuiQui title is a new top layer plus scene data.

TutoTOONS equivalents: L0 is TutoTOONS.Base, L1 is PlayObj (drag, click, CorrectAction, spine, status), L2 is Template0…58, L3 is the imported SharedObject scene files, and L4 is each Builder title.

Diagram 2 · Primitives

Five gestures cover the 28 templates we build

Three primitives come first because QuiQui Care needs them. Steer and Pan are only needed by the movement templates of later titles. Modifiers add behaviour to any primitive. Reactions are shared by all of them.

Modifiers: Spawner makes objects appear or move (t26 t37 t38 t41 t46 t50), Pairs matches two taps (t27), Sequence asks for targets in order (t55). Reactions are data: pose, anim, sfx, voice, fx, swap, coins, wait.

Diagram 3 · What the scenes really use

Scene counts decide the build order

I opened the scene files of the 13 Builder titles: 1845 scenes, of which 1801 use a Builder template. Counting which template each scene carries gives the real weight of each one. Bars are colored by build wave.

Eight templates (T22, T21, T40, T20, T23, T3, T34, T45) cover 83% of the template scenes. The 11 in wave 1 cover 87%. The two ad templates alone appear in 79 scenes, which is why they are retired and not ignored.

Adaptation rules

How a TutoTOONS template becomes a QuiQui template

These rules live in the scene player, so no template or scene can break them.

  • No lives, no game overTemplates with DecreaseLife or RestartScene on failure keep the motion and drop the losing (t26 t37 t38 t50).
  • No timers that end a stepInitTimerBar, AddAutoEndTimer and TimeOut are removed. A step ends on the child's effort (t20 t21 t46 t55).
  • No ads, no paid shortcutsAd rewards become free (t39 t51 t54). Locks open with coins earned in play.
  • Gentle verbsSlice becomes pop, shoot becomes collect, scissors come after comb and dryer (t41 t50 t52).
  • Instant answerEvery valid touch plays a sound and a QuiQui reaction in the same frame.
  • Hint and gentle missThe ghost hand shows the gesture after about 3 s of no input. A miss returns the item to the tray with a soft sound.
Diagram 5 · The player at runtime

One scene from start to end

A scene is a list of steps, and each step is one template with parameters. The player runs them in an Fsm with a transition table, as the project already requires.

English-first naming

Name everything in English, translate only the voice

Play has no text, so the only things that change per language are the voice lines and the few words in the parent area. Everything else is an English id that never changes.

  • Ids, files, code, data keysEnglish, snake_case: kitchen, carrot, quiqui_chewing, t20_drag_snap.
  • Voice by keyvo.kitchen.intro resolves to audio/voice/pt_BR/kitchen_intro.ogg. The family's PT-BR recordings are the first locale, en can follow.
  • Parent-area textGodot TranslationServer with an English base CSV. No hard-coded strings.
  • One-time renameThe current Portuguese file names are renamed once during the restart, and both the builder and the data use the new names.

Why the first slice stays small

The library is only worth building if one loop feels good. Wave 1a tests that with a single template before the other 27 exist. It is also the template with the most evidence behind it: T20 appears in all 13 titles.

Evidence: type and method names from IL2CPP metadata (TutoTOONS.Builder.dll), plus a pass over the scene files of the 13 Builder titles (1845 scenes) that lists which script components each scene carries. The description of each template is inferred from those names. Field values inside the scenes are not readable, and method bodies were not decompiled. The 11 titles without the Builder (Dopples, Fluvsies, Giggle Babies and others) are not in the counts. This is a design proposal. The project flow still requires scope-work → slice-tasks → plan-work before code.
