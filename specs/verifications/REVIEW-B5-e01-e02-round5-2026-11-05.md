## Findings

### must-fix

1. **`game/scripts/components/quiqui_rig.gd:237` — nothing in the suite distinguishes
   `get_visual_global_rect()` from the `Control` box, so the gate's only witness of the character can be
   replaced by the box it exists to stop measuring, and the suite stays 162/162 green.**

   Mutation: first two lines of `get_visual_global_rect()` replaced by `return get_global_rect()` — the
   single most natural "cleanup" of that getter, and the exact pre-BUG-013 shape recast one level up:

   ```
   Tests 162 / Passing 162 / Asserts 633        # box-echoing getter
   ```

   Why it matters: after that edit the rig is indistinguishable from the shipped one at rest (box height
   *is* painted height, `0.574` both), so `_audit_rig_height` passes on a rect the rig never measured, and
   `GeometryOracle._audit_rig_box_is_the_character` (`geometry_oracle.gd:204`) computes
   `dead = box.y - painted.y` from two numbers that are now the same object — always `0`. The cycle's
   conclusion is exactly "a green gate standing in for an unproven requirement"; that gate is one
   refactor away from being unprovable again, and the suite would say nothing.

   The test that looks like it guards this does not: `test_the_character_is_measured_on_its_opaque_pixels`
   (`game/tests/unit/test_quiqui_rig.gd:184`) asserts `painted.size.y < frame_height * 0.95`, but box
   height is `868/1024 = 0.848` of the frame, so the box passes that threshold too; `painted.end.y ==
   box.end.y` and `painted.get_center().x == box.get_center().x` are true of the box by construction.

   Suggested fix: force box and painted to **diverge** in one assertion. Put the rig fixture on a
   non-`0.5` anchor column so `_fit_box_to_art` (`quiqui_rig.gd:107`) bails — `size.x` stays the packed
   640 while the opaque character is ~418 wide on 4:3 — then
   `assert_lt(painted.size.x, box.size.x * 0.8, "the getter measures the art, not the box")`. Honest rig:
   `418.5 < 512` passes; box-echoing rig: `640 < 512` fails.

2. **`specs/bugs/BUG-013-hero-scale-measures-box-not-art.md:49` — the RED-state reproduction recipe does
   not reproduce the numbers it cites.**

   The record says: *"Before the fix the new oracle test reported (rerun by reverting `_fit_box_to_art` in
   review round 2): `rig QuiQuiRig is 0.42 of the canvas height` … and
   `test_the_painted_character_keeps_the_design_height_on_ipad` failed at 0.418."*

   Measured, by doing exactly that (`_fit_box_to_art` returns immediately):

   ```
   casa.tscn 1920x1080 box_h=0.574 painted_h=0.574
   casa.tscn 1920x1440 box_h=0.574 painted_h=0.574
   casa.tscn 2048x1536 box_h=0.574 painted_h=0.574     ← the claimed 0.42
   titulo.tscn … same, 0.574
   Tests 162 / Passing 161 / Failing 1   (only test_the_box_widens_with_the_height_on_a_centre_anchored_rig)
   ```

   The painted height is unaffected because `_update_layout` is height-driven (`factor = box.y / seen.y`);
   `_fit_box_to_art` only shapes the *box*. Disabling the fit **and** restoring the width-limited
   `minf(box.x / seen.x, box.y / seen.y)` still prints `0.574` on all six rows (the opaque rect is
   tall-and-narrow, so the height binds). `0.418` needs the pre-round-3 code that fitted the **1024²
   frame**: `minf(640/1024, 882/1024) × 1024 = 640 px, 640/1536 = 0.417`. So the cited failure came from
   three reverts, not one, and cannot be reached by the function the record names.

   Why it matters: a reviewer (or the next epic) who follows the recipe to confirm the RED state gets
   `0.574` and a green suite, i.e. the record asserts a number the named code path cannot produce — the
   precise defect class this cycle exists to remove. This sentence predates the round-5 commit but ships
   inside the change set (`BUG-013` is new in `bc9a456..739d596`).

   Suggested fix: `"rerun by restoring the width-limited fit in `_update_layout` while
   `get_visual_global_rect()` still returned the 1024² frame (pre-`cd97e88`)"`, or delete the parenthetical
   and cite REVIEW-A round 1's independent table instead.

   records attribute the box/painted equality to the wrong mechanism.**
   ADR-008: *"The rig box is fitted to the art aspect on every layout pass (`QuiQuiRig._fit_box_to_art`),
   **so** the box height and the painted height are the same number."* (DESIGN §3: *"The rig's box width
   follows its height, so the **painted** character … keeps the 55–65 %"*.) The equality is

## What looks right

- **The requirement genuinely holds on canvases nobody measured.** I put both scenes through a
  `SubViewport` at `1280×720`, `2560×1440`, `1200×1600` (portrait 3:4), `1600×1200` (5:4) and
  `2732×2048`: painted height `0.574`, feet `0.780` / `0.926`, horizontal offset from the canvas centre
  `0.0` on all ten rows. The fix is not tuned to the three tabulated aspects.
- **Re-anchoring and layout ordering.** `_refit()` runs from `_ready`, `_apply_expression` and
  `NOTIFICATION_RESIZED`; the `BOX_FIT_EPSILON` early return makes the second pass a no-op, so the offset
  rewrite inside `NOTIFICATION_RESIZED` converges instead of looping. A rig mounted into a full-rect stage
  after `_ready` still lands on `0.574`.
- **`_fit_box_to_art` fails safe.** It only fits a centred `0.5/0.5` column; with any other anchor column
  it bails and `_update_layout` keeps the height correct (width stale). Height and feet survive; only the
  tap surface stops matching the character — which is why consider 8 exists.
- **The gate does bite on the failure it was built for.** Reverting the `minf`→height-driven factor
  reproduces the class of failure (the probe drops to `0.231`); the box-echoing getter is the one shape
  that walks through (must-fix 1).
- **Round-3 must-fix "the newline test does not discriminate" is now closed, proved by mutation.**
  Restoring `^res://…$` in `wish_bubble.gd:20` fails `test_a_newline_suffixed_path_is_refused` on
  `"…/cenoura.png\n"` (162 → 161), and `test_a_trailing_newline_is_refused` covers
  `"mesa\n" / "mesa\r\n" / "mesa\n\n"` through both `Ids` and `SaveData`. `Ids.PATTERN` really is
  `\A[a-z0-9_]{1,64}\z`; `log.gd:39`'s `^…$` is the documented auditor-owned exception (`ids.gd:9-11`) and
  is unreachable because `_safe_id` strips edges first.
- **Fail-closed discipline in the oracle.** `GeometryOracle._audit_rig` reports a non-`Control` rig, a rig
  with no painted area, and a scene that forgot a declared group; `opaque_rect()` returns an empty rect
  (not the frame) for unreadable art and `_update_layout` still renders the frame while reporting nothing
  — the `PlaceholderTexture2D` path ends in `no painted geometry`, verified by test.
- **`required_groups` is no longer opt-in.** It lives in `CARE_ROOM_SPEC` and `TITLE_SPEC`, so a scene
  that forgets `add_to_group` is a finding; `test_a_scene_that_forgets_a_declared_group_is_caught` asserts
  exactly 3 findings, so one incidental message cannot satisfy it.
- **No CONVENTIONS regression in the product code.** `gdlint` + `gdformat --check` green, `type_gate`
  green (strict typing held through the `Variant`→`Rect2` duck-typed hop at
  `geometry_oracle.gd:_painted_rect`), no network/ad/telemetry, save paths still isolated by `TestReset`,
  every new script carries its `# story:` tag (`trace-stories.sh --strict` passes), and
  `quiqui_rig.gd`'s new code is table/constant driven with no boolean-flag state machine.
- **The 16:9 and 4:3 scenes still compose.** Doors outside the rig box (`674..1374` vs `64..232` /
  `1816..1984` at 4:3), dots 36 px, HUD 36/36, Play button still receives taps above the rig because it is
  the later sibling, mouth zone inside the visible art, `carente` pose keeps the same seen height.
