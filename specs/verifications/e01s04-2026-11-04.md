## Behaviour proven

**TapButton**
- one fire per finger tap; the `device == -1` echo is ignored; a real mouse (`device == 0`) is a legitimate tap
- 20 consecutive taps fire 20 times (no accumulation or swallowing)
- disabled button ignores input
- the hit box is never smaller than 120×120, and the spring never changes it — only `Visual` scales
- three-step spring `(1.14,0.88) → (0.94,1.07) → (1,1)` ends by itself, even when a single frame is longer than a keyframe

**QuiQuiRig**
- layer order `Body(0) < Outfit(10) < Expression(20) < Headwear(30) < Neck(40) < Glasses(50)` — the outfit can never hide the face (DESIGN §4.5)
- breathing oscillates the pivot scale around a **foot-anchored** pivot: the feet never leave the floor
- a neutral face blinks for 130 ms and reopens; a held expression (`careta`) is never overwritten by a blink
- expression/outfit art switches by id; missing art and invalid ids (`"Maria Clara"`, `"../etc/passwd"`) are refused without changing what is on screen
- the mouth zone is created with real size inside the visible art

## Defects found by the tests

1. **Squash consumed one keyframe per `advance()`** — a 0.5 s frame left the spring half-open forever. Both springs now consume the delta in a loop.
2. **The first `set_expression()` was a no-op** — the "already this expression" guard short-circuited before any art was applied, so the rig started invisible. `expression_id` now starts empty.
3. **Lambda capture is by value** — `var fired := 0` inside a test never changed when a signal lambda incremented it. Counters in tests must be members (the same trap cost a cycle in e01s01).
