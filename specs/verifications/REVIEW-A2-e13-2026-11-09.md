## Summary

The tests pass, but several stories do not do what their acceptance criteria say when a child plays them through `ScenePlayer`. Most of the defects are where the def loader and the templates meet, and the tests do not cover that seam. The tests mount templates directly, or they call `_gui_input` on the target control, so they never meet `StepParams`, hit-testing or the real node names. Six defects reach the child or break an explicit bar:
- A `t21` def can be rejected for its spec'd `count_n` mode, or can be stuck forever on the default mode.
- A closet def with two items for one slot cannot load.
- Dressing saves the look, but QuiQui does not change.
- The reward's coins never fly, because the template looks for the wrong HUD node name.
- The lane game counts a basket that waits under the fruit as a miss, and it catches fruit that is still at the top of the screen.
- One function is over the 20-line bar.

The input surfaces are real: every template builds its own pad, buttons or tool. The Ids grammar, the closed registry, the `device == -1` filter, the 120 px floor and the 59.5% arithmetic are sound.

## Findings

### A1 — must-fix — `t21_touch_each` mode grammar: `count_n` is rejected and the default mode never completes
- **File:line:** `game/scripts/core/step_params.gd:16` (`T21_MODES = ["any", "single", "toggle"]`), `:32`; `game/scripts/resources/step_def.gd:15` (`mode` defaults to `"single"`); `game/scripts/components/tap_primitive.gd:28-35` (`progress()` knows only `any`, `count_n`, `toggle`, else `return 0.0`).
- **Evidence:** e13s02 AC3 names `any`, `count_n`, `toggle`. The loader rejects any `count_n` def with `bad_mode` before the player mounts it. It accepts `single`, which is also the default when a def leaves `mode` blank. `TemplateKit.mode_or` returns `"single"` (the value is not empty), and `TapPrimitive.progress()` then returns 0.0 for ever, so the step never ends. The only `count_n` tests (`test_t21_touch_each.gd:31,56`) mount the template directly and never pass through `SceneDefLoader`. `test_step_params.gd:88` always sets `mode = "any"`, so neither defect can show.
- **Fix:** Set `T21_MODES` to `["any", "count_n", "toggle"]` (match TapPrimitive), and reject or normalise `single` for t21. Add a loader-level test for each mode and for a def with no mode.

### A2 — must-fix — `StepParams` rejects a repeated slot id, so a closet with two items for one slot cannot load
- **File:line:** `game/scripts/core/step_params.gd:46` (puts `step.slot_ids` in the `_clean_ids` list), `:72-79` (`_clean_ids` fails on `seen.has(id)`); `:107-110` (`_dress` requires `slot_ids` to pair 1:1 with `item_ids`).
- **Evidence:** In t45, `slot_ids[i]` is the slot of `item_ids[i]` (`t45_dress_decorate.gd:106-113`). Two neck items need `slot_ids = ["neck","neck"]`, which `_clean_ids` rejects with `bad_id`, so `SceneDefLoader.validate` returns null. That makes the closet impossible: every slot can show only one item. The single-item `dress_probe.tres` hides the defect. The same rule also stops two map doors from opening the same scene (`destination_scenes`).
- **Fix:** Check `slot_ids` and `destination_scenes` with the grammar only, not for uniqueness. Keep the uniqueness check for `item_ids`, `destination_ids` and `category_ids`. Add a test with two items in one slot.

### A3 — must-fix — dressing saves the look, but QuiQui never changes (not on the tap, not on re-entry)
- **File:line:** `game/scripts/templates/t45_dress_decorate.gd:60-72` (`snap` calls `ProgressManager.equip` and `play_hit` only); `:85-93` (`bin` calls `clear_slot` only); `game/scripts/scenes/scene_player.gd` (no call to `ProgressManager.dress`; the only caller in the tree is `closet.gd:127`); `QuiQuiRig` does not listen to `progress_changed`.
- **Evidence:** e13s05 AC2 says "items snap onto slots". Verification steps 3–4 say "drag an outfit onto QuiQui → it snaps … open the closet again → she is still dressed the same way". In the player the scarf stays in the strip, and the rig never gets `set_accessory`/`set_outfit`. The player also does not dress the rig when it boots. `test_surfaces_player_e2e.gd:72-84` checks only the save, so it passes on an unchanged QuiQui.
- **Fix:** After a successful `equip` or `clear_slot`, call `rig.set_accessory`/`set_outfit` (or `ProgressManager.dress(ctx.rig)`), and dress the rig when the player mounts. Assert the rig's accessory in the player e2e.

### A4 — must-fix — the reward's "coins fly to the HUD" never runs in the player
- **File:line:** `game/scripts/templates/t32_reward.gd:80` (`get_node_or_null("CoinTicketHud")`); `game/scenes/scene_player.tscn:74` (`[node name="CoinHud" …]`, script `coin_ticket_hud.gd`).
- **Evidence:** The node name is wrong, so `_fly_coin` always gets null and returns without doing anything. e13s05 AC4 ("coins fly to the HUD") is not met through `ScenePlayer`. No test asserts a fly.
- **Fix:** Resolve the HUD through `PlayerNodeTable` (register it in `_register_nodes`) or use the real node name. Add a player e2e that spies on `fly_coin`.

### A5 — must-fix — `t50_lanes` "catch" ignores where the fruit is
- **File:line:** `game/scripts/components/spawner.gd:38-47` (`take_lane` removes every live row in the lane, at any age); `:82-90` (`_age` counts a miss when the lifetime ends, whatever lane the basket is in); `game/scripts/templates/t50_lanes.gd:104-116` (the catch happens only on finger lift); test `game/tests/integration/test_t50_lanes_e2e.gd:35-45` (it catches a fruit spawned on the same tick, age 0, at the top of the field).
- **Evidence:** A child who parks the basket under a falling fruit and waits scores nothing: the fruit reaches the basket and counts as a miss. A lift anywhere in a lane takes every fruit in that lane, even one that just appeared at y≈0. e13s08 says "objects are caught" and verification step 3 says "Objects arrive; catch one → it scores", but what the child sees on screen does not match how the game scores.
- **Fix:** Catch on arrival: when a row reaches the end of its lifetime, it scores if `basket_lane == row.lane`, else it is a quiet miss. The lift only moves the basket. Re-point the e2e at a fruit that has actually fallen.

### A7 — should-fix — the reward tap pays for a cycle that was never played
- **File:line:** `game/scripts/autoloads/care_loop_manager.gd:128-133` (`collect_reward` calls `_grant_cycle_reward` in any state); `game/scripts/autoloads/progress_manager.gd:175-176` (`complete_cycle` adds `completed_cycles + 1`).
- **Evidence:** In a fresh game (IDLE, cycle 0), `test_surfaces_player_e2e.gd:30-41` taps the star and asserts that coins went up. So the child gets +5 coins, +1 ticket and +1 completed cycle with no care done. After each CELEBRATE→IDLE, the next visit pays for the new cycle before it is played. This breaks the threat model's rule that every mint stays once per cause: the cause is a finished cycle.
- **Fix:** Let `collect_reward` pay only in CELEBRATE (or only when `reward_paid()` is already true). In IDLE, show the star without paying.

### A8 — should-fix — `t45` is a tap list, not the dress or decorate screen AC2 describes
- **File:line:** `game/scripts/templates/t45_dress_decorate.gd:75-82` (`place` has no input surface; only `test_t45_dress_decorate.gd:51` calls it); `:42-45` (`categories()` only returns data, with no category control); `:133-139` (a tap snaps; there is no drag onto QuiQui); `:142-144` (the bin clears only `_last`, which is empty after re-entry, and plays no sound); `:69` (a repeat tap on the same item counts toward `repeat_count`, because `equip` is idempotent and returns true).
- **Evidence:** e13s05 AC2 asks for a category strip (`CategoryController` equivalents), snap or free place, and a bin that "returns an item with a soft sound". Free place cannot be reached by touch, categories do nothing, and the bin is silent and does nothing after re-entry. BUILDER_REUSE_MAP lists `casinha` as "t45 (free_place)".
- **Fix:** Wire free place to a drag on the pad, make categories filter the row, play `on_miss_sfx_id` (or a bin SFX) on the bin, let the bin act on the worn slot and not on `_last`, and count only snaps that change something.

### A9 — should-fix — rub modes are template branches, `mode` is ignored, and the erase radius is missing
- **File:line:** `game/scripts/components/rub_primitive.gd` (no mode field; `CELL_EDGE: int = 4` at `:6` is the only resolution); `game/scripts/templates/t23_erase.gd:8` / `t40_draw_fill.gd:8` (hard-coded `bind(ctx, false/true)`); `game/scripts/core/step_params.gd:34-35` (t23/t34/t40 check only the threshold, so any `mode` string loads).
- **Evidence:** e13s01 AC3 puts `clear`/`leave`/`reveal` in the primitive, and its frozen contract says "Both are data flags, not template branches". e13s04 AC4: "the erase radius and the sound come from the def". No radius parameter exists, and the 4×4 grid is fixed. The tests set `mode = "clear"`/`"reveal"`, which nothing reads.
- **Fix:** Give `RubPrimitive` a `mode` and a def-driven cell size or radius, validate `mode` per rub template in `StepParams`, or restate the AC.

### A10 — should-fix — rub layers without art are white rectangles, and the bathroom chain does not rinse the foam
- **File:line:** `game/scripts/components/rub_surface.gd:126-133` (no art → `ColorRect` at `Color(1,1,1,0.8)`, sized to the rig's whole rect at `:44-49`); `:72-74` (owned layers are freed when the step ends); `game/data/scenes/bathroom_probe.tres` (rinse erases `water`, dry erases `towel`).
- **Evidence:** `foam`, `water`, `mud` and `dust` have no PNG under `assets/art/` (checked), so they draw as flat white boxes over QuiQui. `towel` is the towel item icon stretched over her. The foam from step 1 is freed when soap ends, and rinse then erases a new white box. So the rinse step never removes the foam, which is what e13s04 means by soap → rinse → dry. This also goes against the glossy-art rule.
- **Fix:** Ship layer art (or a def-named effect), let rinse claim the foam layer (`item_ids = ["foam"]`) and dry claim the water, and keep the layers between steps of one def.

### A11 — should-fix — "each object answers with its own reaction" and "animates away" are not implemented
- **File:line:** `game/scripts/templates/t21_touch_each.gd:81-82` and `game/scripts/templates/t34_rub_reveal.gd:66` (both use the step-wide `on_hit_pose`/`on_hit_sfx_id` through `TemplateKit.play_hit`); `t34_rub_reveal.gd:65` (`set_alpha(index, 0.0)` is an instant cut); `t21` gives no visible mark to a spent target.
- **Evidence:** e13s02 AC4 says "each target plays its own reaction and marks itself". e13s01 says "each layer animates away" and "their reveal reactions come from the StepDef". Every target and every layer plays the same reaction, and a reveal is a jump cut.
- **Fix:** Add per-item reactions (a parallel array or a reaction table keyed by item id), a spent-mark state on the TapButton visual, and a short fade tween for reveal.

### A12 — should-fix — the Pan `follow` mode is never used when the room opens, and the view size is frozen
- **File:line:** `game/scripts/templates/t25_map.gd:29-36` (`setup` never calls `follow`; no def field names a follow target); `:80-82` (only `test_t25_map.gd:56-58` calls `follow`); `:34`, `:204-207` (`view_size` is read once at setup; only a test calls `apply_view`).
- **Evidence:** e13s03 AC2: "`follow` (auto-scroll to a target, used when the room opens)". On a resize or rotation, the clamp still uses the old canvas.
- **Fix:** Add a def field for a follow target (or follow the first open door) in `setup`, and update `view_size` from the host's `resized` signal.

### A14 — should-fix — player tests skip hit-testing; the rig covers the map and lane pads; t21 and t34 have no player e2e
- **File:line:** `game/tests/helpers/player_test_case.gd:29-30` (`send` calls `control._gui_input` on the chosen node); `game/scripts/core/template_kit.gd:97-104` (`mount_pad` puts the pad just above Background, below the rig); `game/scenes/scene_player.tscn:51-59` (QuiQuiRig is 640 px wide and covers 20.6%–78% of the height); `game/scripts/components/quiqui_rig.gd:67` (`MOUSE_FILTER_STOP`).

Add one test that resolves the target with a point-in-rect search over the sorted children (or `Viewport.gui_pick`, if the version has it). Add player e2e tests that tap through `touch_each_probe` and rub through `rub_reveal_probe` to completion.

## What I checked and found sound

- Every template builds its own input surface: TapButtons (t21, t32, t45, t51, t0), the TouchDraggable tool (t23, t34, t40) and TouchPads (t25, t50). Teardown frees the tool, layers, pad, world, wish, strip and items. The bathroom, map and lanes e2e tests show the tree is restored after Home.
- The player e2e tests use real `InputEventScreenTouch`/`Drag` events, not template methods, for title, reward, prize, dress, bathroom, map and lanes (hit-testing aside, A14).
- `TouchPad._gui_input` drops `device == -1`, `CleaningRub.note_tray` filters mouse echoes, and the tests inject the echo on purpose (`test_map_player_e2e.gd:66-74`, `test_t34_rub_reveal.gd:27-37`).
- Second finger: `PanPrimitive` and `SteerPrimitive` let one owner finger hold the gesture, through `Fsm` (`STATE_*`, `LEGAL_EDGES`). No boolean-flag state machines were added.
- Strict typing: no untyped `var`, parameter or return in the 58 changed files. gdlint and gdformat are clean, every changed file has a `# story:` tag, every file is ≤ 300 lines (`progress_manager.gd` is exactly 300), and no `game/scenes/*.tscn` was changed.
- Ids: `ItemArt.path_for`, `SceneNav.open`, `t25._resolve`, `t45.snap`, `t51.pick`, `ProgressManager.equip/clear_slot/place_furniture` and `StepParams._shared/_clean_optional` all validate before a save or a `res://` lookup. Map destinations resolve through `SceneCatalog`, and no def string is joined into a path.
- No `HTTPRequest`, `HTTPClient` or `WebSocketPeer`, no ad verbs (source scans in t32 and t51), and no wallet reads in t25.
- The scenes column matches the per-template counts in `QUIQUI_BUILDER_DESIGN.html` (274, 197, 147, 131, 130, 121, 65, 13, 8, 7, 14, 392). The built rows add up to 1,071 / 1,801 = 59.5%. `TemplateTableGate` derives the sum and has failing-input tests for a missing row, a wrong scope and a wrong def.
- Pay-once on re-entry (t32) and no second pick in one visit (t51) are enforced and tested through the player.
- The malformed-def perimeter (`StepParams`) rejects NaN/INF thresholds, mismatched map arrays, bad locks and out-of-range lane numbers (except for the A1 and A2 over-rejections and gaps).
