## Summary

The primitives are small, typed and tagged, and the security rules hold: no network, ids validated before
saves, destinations resolved through `SceneCatalog`, no ad verbs. But most templates are **logic objects that
`ScenePlayer` cannot drive**. `ScenePlayer` calls only `setup`, `advance`, `progress` and `teardown`, and it
forwards no input. So t23, t40, t25, t45, t32, t51 and t50 build no tap or drag surface and draw nothing. Five
of the nine probe defs cannot be finished by a child. The unit tests call test-only methods directly
(`release_on_lane`, `pick`, `collect`, `snap`, `activate`, `note_rub`), so the suite stays green while the
"Playable Vertical Target" of five stories is not met. The rub coverage ratio also over-counts on the real
(elliptical) rig hull, and the coverage figure in the wave-1 gate is checked against itself.

## Findings

### A1 — must-fix — rub coverage over-counts on any non-rectangular hull
- **File:** `game/scripts/components/rub_primitive.gd:27-34`, `:74-102`
- **Evidence:** `rub_at` marks the bbox cell of any point inside the hull (`_cell_key`), but `_area_count`
  counts only cells whose **centre** is inside the hull. On `QuiQuiRig`'s hull (a 12-point inscribed ellipse,
  `quiqui_rig.gd:393-405`) the four 4×4 corner centres lie outside the ellipse, because (0.75² + 0.75² = 1.125 > 1).
  That gives `area = 12`. Points inside the ellipse still fall in those corner cells (for example normalised
  (0.2, 0.2)), so `_marked` can hold 16 keys over an area of 12. With the 0.9 threshold, 4 corner cells plus 7
  real cells (58% of the body) complete the step, and `t34` reaches 1.0 early. All tests use square hulls, so
  this path is never exercised. This breaks SC-e13s01-P0-02 ("reaches 1.0 only when the area is done").
- **Fix:** mark a cell only if its centre passes `Geometry2D.is_point_in_polygon`, or compute the ratio over
  `marked ∩ area_cells`. Add a test with an ellipse/diamond hull that rubs only the corner cells.

### A2 — must-fix — t23_erase / t40_draw_fill cannot be played in `ScenePlayer` (bathroom probe never ends)
- **File:** `game/scripts/components/cleaning_rub.gd:14-24`, `game/scripts/templates/t23_erase.gd:8-9`,
  `t40_draw_fill.gd:8-9`, `game/data/scenes/bathroom_probe.tres`
- **Evidence:** neither template creates a `TouchDraggable` tool (unlike `t34._build_tool`), and `ScenePlayer`
  forwards no input. So in a real run `begin_gesture` / `note_rub` are never called, `progress()` stays 0, and
  all three steps of `bathroom_probe` hang. The def's `loop_sfx_id` and `item_ids` (`foam`/`water`/`towel`) are
  never read: `CleaningRub` never calls `_rub.set_loop`, and no layer is drawn. This misses e13s04 AC3/AC4
  ("the layer's visual, the tool and the SFX come from the def"). AC3 ("DisableTools maps to disabling the
  tray") is also missed: `tray_accepts()` only gates `note_tray`, a counter that only tests call. The real
  `TrayZone` children are never disabled.
- **Fix:** build the tool and the layer in `CleaningRub.bind` (share `t34`'s `_build_tool`/`_make_layer`),
  bind the loop from `loop_sfx_id`, and set the tray's children to `enabled = false` / `MOUSE_FILTER_IGNORE`
  while `_holding`. Prove it with a ScenePlayer-level test that rubs through `TouchSim` on the tool.

### A3 — must-fix — t25_map is an API with no map: no input, no icons, no navigation, locks never read the care loop
- **File:** `game/scripts/templates/t25_map.gd:13-59`, `:120-141`; `game/data/scenes/home_map.tres`
- **Evidence:** the template creates no nodes, handles no `InputEvent`, has no `progress()`, and never calls
  `SceneManager.request_def` with the id that `activate` returns. `set_open_steps` is the only source of lock
  state, and no production code calls it. So "locks read the care loop" (AC3, threat-model row) is not true:
  every lock stays shut forever. `home_map.tres` has no `destination_positions` (all resolve to `Vector2.ZERO`),
  and `StepDef` has no icon field, which misses AC4 ("id, position, icon, lock rule, scene"). AC3's wish bubble
  is replaced by a `_pointed` string. AC2's "one finger at a time; a pan never starts on a tap target" has no
  code. `_refused` is sticky and is never cleared after a later success.
- **Fix:** read `CareLoopManager` completed steps in `setup`, build one `TapButton` per destination with the
  def icon at the def position inside a pannable child `Control`, route touch begin/move/end through
  `PanPrimitive` with touch-index ownership, and on `end_allows_tap()` call `request_def(scene_id)`. Add
  positions and icons to `home_map.tres`.

### A4 — must-fix — t50_lanes never ticks and cannot be steered under `ScenePlayer`
- **File:** `game/scripts/templates/t50_lanes.gd:24-40`
- **Evidence:** the spawner advances only in `tick()`, but `ScenePlayer._tick_template` calls `advance(delta)`,
  which t50 does not define. So nothing spawns. `note_event` is never called by production code. Even if it
  were, it handles only `InputEventScreenDrag`, and `SteerPrimitive.move_to` returns early because `begin()` is
  never driven by a real touch. `release()` / `take_lane` are reachable only through the test seam
  `release_on_lane`. Any finger index steers (no ownership), and items have no nodes or art. This misses e13s08
  AC2/AC4 and the story's playable target. The "zero orphans" claim (SC-e13s08-P0-04) is vacuous (see A13).
- **Fix:** add `advance(delta)` with a fixed-step accumulator that calls `tick()`. Drive
  `begin`/`move_to`/`release` from the owned touch index (`ScreenTouch` press/release, `ScreenDrag`, device -1
  filtered). Catch on release. Render spawned items as child nodes freed on catch, miss and `stop()`.

### A5 — must-fix — t45 / t32 / t51 have no tap surface; t45 can never finish a step
- **File:** `game/scripts/templates/t45_dress_decorate.gd:17-18`, `:27-56`; `t32_reward.gd:10-38`;
  `t51_prize_pick.gd:9-37`
- **Evidence:** `t45.progress()` always returns `0.0`, so a dress step never completes. This is the HIGH
  "step with no exit" DoS row in the threat model. There is no category strip (AC2 asks for a scrolling
  strip), no draggable item, and the bin has no soft sound (only `_plays += 1`). `t32` and `t51` expose
  `collect()` / `pick()`, but no button calls them. On first entry the step hangs at 0. On re-entry it
  completes on the first frame, before the child sees the star or the prize. AC4 of e13s05 ("collected with a
  tap, coins fly to the HUD, the star appears") is not met.
- **Fix:** each template builds its own `TapButton`s/`TouchDraggable`s from `item_ids` (icon by id) and wires
  them to `snap`/`bin`/`collect`/`pick`. Give t45 a completion rule (for example a "done" verb, or N items
  placed). Play `on_miss_sfx_id` on bin. On re-entry, show the lit star and let one tap continue rather than
  auto-completing.

### A6 — must-fix — t21 targets are invisible and their squash is frozen (test seam shipped)
- **File:** `game/scripts/templates/t21_touch_each.gd:73-82`; also `t34_rub_reveal.gd:123-136` (tool)
- **Evidence:** `_make_button` sets `button.manual_step = true`. `TapButton._process` then never calls
  `advance`, so after `_activate` the `Visual` stays at the first squash scale for good. AC2's "squash-spring
  feedback" fails in production. The button's `Visual` is an empty `Control` and no texture is assigned from
  the item id, so `apple`/`grape` draw nothing. That breaks the frozen contract "Targets are pictures" and the
  rule "every prompt MUST be visual". `t34`'s `RubTool` is likewise an empty 120×120 `TouchDraggable`.
- **Fix:** drop `manual_step = true` (tests can set it). Add a `TextureRect` to `Visual` from an id→art
  catalogue (same pattern as `SfxCatalog`). Give the rub tool art from the def.

### A7 — must-fix — the wave-1 coverage gate is a tautology
- **File:** `game/tests/unit/test_template_registry.gd:23-56`
- **Evidence:** `share = "%.1f%%" % (100.0 * 1071.0 / 1801.0)` compared with `"59.5%"` is constant arithmetic
  and can never fail. `TEMPLATE_TABLE.md` has no per-template scene counts, so nothing is derived from the
  table. That misses e13s09 AC4 ("coverage is computed, not asserted … fails if the claim disagrees with the
  table") and is exactly the story's named risk ("a registry test that passes vacuously"). The test never reads
  `TemplateCatalog.SCRIPT_FOR_ID`, so a catalog id with no row passes. `_assert_consumer` checks only that
  `<scene>.tres` exists, not that it uses the template. A row could name any def.
- **Fix:** add a `scenes` column per row, sum the built rows and compare the result with the number parsed
  from `SCOPE_LATEST.yaml`. Assert catalog ids (minus `t_stub`) equal the built rows. Load each consumer def
  and assert one step has that `template_id`. Add a negative case (a fixture table with a missing row fails).

### A8 — should-fix — the three rub modes are dead data
- **File:** `game/scripts/components/rub_primitive.gd:8`; `game/tests/unit/test_rub_primitive.gd:43-55`
- **Evidence:** `mode` is assigned but never read, so `clear`, `leave` and `reveal` behave the same. The frozen
  contract "Reveal is irreversible, clear is not. Both are data flags" has no code. The test only checks that
  the string round-trips, which tests implementation, not behaviour (speculative generality).
- **Fix:** either implement the mode difference (for example `clear` resets marks on `begin`, `reveal` keeps
  them) with a behavioural test per mode, or remove the field and note in the spec that modes are template-side.

### A9 — should-fix — t21 soft-locks on `toggle`, an unknown mode, or `repeat_count` > targets
- **File:** `game/scripts/components/tap_primitive.gd:25-30`; `game/scripts/templates/t21_touch_each.gd:58-61`
- **Evidence:** `progress()` returns `0.0` for `toggle` and for any unrecognised mode (a typo), and `count_n`
  uses `goal = repeat_count` with no cap at `item_ids.size()`. Each case is a step with no exit (threat-model
  HIGH DoS row).
- **Fix:** define toggle completion (for example all targets on), reject unknown modes in
  `SceneDefLoader.validate`, and clamp `goal` to the number of distinct targets.

### A10 — should-fix — t0_title's one verb is a bare `Button` and it disables Home
- **File:** `game/scripts/templates/t0_title.gd:28-54`
- **Evidence:** it uses a stock `Button` with no icon or glow (AC3 "one glowing target"), no 120 px floor and
  no `TapButton`. That gives up the project's single tap surface and its echo-filter convention. `_quiet_host`
  sets `MOUSE_FILTER_IGNORE` on `ScenePlayer`'s `HomeButton`, which goes against the threat-model mitigation
  "home is live in every state", and nothing restores it. `interactive_count` scans only direct children
  (TrayZone descendants stay interactive), so SC-e13s05-P1-03 is shallow. `_button` is never read.
- **Fix:** use a `TapButton` with glowing title art at ≥ 120 px. Leave Home alone, or restore filters in
  `teardown`. Count interactive nodes recursively.

### A11 — should-fix — `ProgressManager.clear_slot` does not emit `progress_changed`
- **File:** `game/scripts/autoloads/progress_manager.gd:149-157`
- **Evidence:** `equip` emits `progress_changed` after `save()`, but `clear_slot` does not. Listeners (rig,
  closet, HUD) keep showing the binned item until a later event.
- **Fix:** emit `progress_changed` after a successful erase and save. Assert the signal in
  `test_t45_dress_decorate`.

### A12 — should-fix — rationale docs deleted to stay under the 300-line bar

### A13 — should-fix — several named scenarios are vacuous or missing
- **File:** `game/tests/integration/test_t50_lanes_e2e.gd:20-21`, `test_bathroom_rub_e2e.gd:15-42`,

### A15 — should-fix — Duplicated Code across templates and hidden autoload globals
- **File:** `t34_rub_reveal.gd:72-79` = `cleaning_rub.gd:98-105`; `t34:162-171` ≈ `t21:91-100`;
  `t45:73-77` = `t51:57-61` ≈ `t32:54-58`; `_mode()` in t21/t23/t34/t40; `t23_erase.gd` ≈ `t40_draw_fill.gd`
- **Evidence:** the same hull-target fallback, reaction-batch builder, `Engine.get_main_loop()` autoload

- **Fix:** move `hull_target()`, `play_hit(step_def)`, `progress_sink()` / `care_loop()` and `mode_or(default)`

### A16 — consider — a `ScrubLoop` node accumulates on the host per rub step
- **File:** `game/scripts/components/scrub_gesture.gd:21-24` (via `rub_primitive.gd:23`, `cleaning_rub.gd:20-23`)
- **Evidence:** each template instance has its own `ScrubGesture`, and each adds a `ScrubLoop` to
  `ctx.host`. `teardown` only stops it, so the three-step bathroom leaves three players under `ScenePlayer`.
- **Fix:** free the loop in `RubPrimitive.release_all()`, called from `teardown`.

### A17 — consider — `Spawner.seed` shadows the global `seed()`, and `miss_count` is a public mutable
- **File:** `game/scripts/components/spawner.gd:6`, `:16`
- **Evidence:** this triggers Godot's `SHADOWED_GLOBAL_IDENTIFIER` warning, and the mutable counter is
  declared among the private fields.
- **Fix:** rename to `rng_seed`, and expose `misses()` as read-only.

### A18 — consider — t34 covers the whole player with white rects and leaves resolved layers transparent
- **File:** `game/scripts/templates/t34_rub_reveal.gd:110-120`, `:22-29`
- **Evidence:** generated layers are full-rect white `ColorRect`s added last to `ScenePlayer`, on top of the rig,
  the tray and Home. Layers resolved from `nodes` are set to alpha 0 and never restored in `teardown`.
- **Fix:** parent layers to the scrub target's rect and use def art. Restore alpha on non-owned layers.

### A19 — consider — the prize is stored as an outfit slot, and the pick lasts for the life of the save
- **File:** `game/scripts/templates/t51_prize_pick.gd:26`, `:50-54`
- **Evidence:** `equip("prize", id)` puts a non-outfit key into `equipped_outfits` (outside `SaveData.SLOTS`).
  The "one pick" lock then holds forever, not per cycle, so the spec's "once-only rule is a service value"
  is not a service. `t45.snap` also has no ownership check, though the threat-model row says
  "owns_furniture before any save".
- **Fix:** add a typed `prizes` field with a `SaveData.version` bump, or a `PrizeLedger` keyed by cycle.

### A20 — consider — small boolean flag clusters
- **File:** `t32_reward.gd:6-7` (`_star`/`_collected`, always set together), `cleaning_rub.gd:8-10`
  (`_latched` + `_completions` + `_holding`)
- **Evidence:** these are redundant or orthogonal bools where the Fsm rule (or a single field) is preferred.
- **Fix:** collapse `_collected` into `_star`, and derive `_completions` from `_latched`.

### A21 — consider — a duplicate id in t21's `item_ids` leaks a button
- **File:** `game/scripts/templates/t21_touch_each.gd:64-71`
- **Evidence:** `_buttons[target_id] = …` overwrites, so the first button is never freed by `teardown`. The
  fixed `160 * index` x-layout also overflows the tray past about 12 items at 1920 px.
- **Fix:** skip duplicates (or reject them in the loader), and lay out the buttons in a container.

### A22 — consider — the rub point is hull-tested twice by two `ScrubGesture`s
- **File:** `t34_rub_reveal.gd:131-140`, `rub_primitive.gd:27-29`
- **Evidence:** `TouchDraggable._scrub` consumes the point, then `RubPrimitive._gesture` consumes it again with
  a second counter. AC2 says `scrub_gesture.gd` owns the counting (one owner).
- **Fix:** let `RubPrimitive.rub_at` trust a point already accepted by `scrubbed`, or have the tool expose its
  gesture.
