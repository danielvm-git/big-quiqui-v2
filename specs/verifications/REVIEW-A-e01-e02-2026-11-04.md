## Findings

### must-fix

1. `game/tools/build_casa_scene.gd:24,78-79` (same shape in `build_titulo_scene.gd:21,53-54`) + `game/tests/helpers/geometry_oracle.gd:142,167-176` —
   **On the iPad canvas QuiQui is painted at 42 % (casa) / 46 % (titulo) of the viewport height, not 55–65 %; the oracle and the FIX report measure the Control *box* (0.574), not the art.**
   The rig box is pinned with a *fixed pixel width* (640 / 700 px) and a *ratio height* (0.574 × H). `QuiQuiRig._update_layout` fits the 1024×1024 art with `factor = min(box.x/art.x, box.y/art.y)` (`quiqui_rig.gd:280`), so on a 4:3 canvas the width is the binding side and the box is mostly empty above her head.
   Measured headless (SubViewport, 3 frames, `get_visual_global_rect()` vs `get_global_rect()`):

   | scene | canvas | box h | box feet | **painted h** | painted feet |
   |---|---|---|---|---|---|
   | casa | 1920×1080 | 0.574 | 0.780 | 0.578 | 0.780 |
   | casa | 2048×1536 | 0.574 | 0.780 | **0.418** | 0.780 |
   | casa | 1920×1440 | 0.574 | 0.780 | **0.446** | 0.780 |
   | titulo | 2048×1536 | 0.574 | 0.926 | **0.457** | 0.926 |
   | titulo | 1920×1440 | 0.574 | 0.926 | **0.487** | 0.926 |

   `DESIGN.md` §3 (line 31) and ADR-008 require 55–65 % on the primary device. The cycle's headline "Rig height ratio … 0.430 → **0.574**" for 4:3 (FIX-e01-e02 table, ADR-008 Consequences) is a box measurement; the child sees 0.42–0.49. Feet and centring *are* correct. This is exactly the failure mode the cycle exists to remove: a green oracle standing in for an unproven requirement. `_audit_rig_height` takes `control.get_global_rect()`, and `QuiQuiRig.get_visual_global_rect()` — the thing that actually measures the art — already exists and is unused by the oracle.
   **Fix:** (a) make the oracle's height check use the painted rect (`rig.get_visual_global_rect()` when the node is a `QuiQuiRig`), keep the box check as a second assertion, and add a RED test with a narrow box on a tall canvas; (b) then fix the layout so the width tracks the height (e.g. size the box from the canvas height: anchor width as `RIG_HEIGHT_RATIO × art_aspect × H`, via a resize hook or an `AspectRatioContainer`, instead of a fixed 640 px); (c) correct FIX-e01-e02, ADR-008 and BUG-002 numbers afterwards.

### should-fix

1. `game/scripts/core/ids.gd:10`, `game/scripts/components/wish_bubble.gd:20`, `game/tests/unit/test_ids.gd:11` — **`Ids` does not implement the contract it claims to own, and the test pins the wrong string.**
   `CONVENTIONS.md:78` mandates `\A[a-z0-9_]{1,64}\z`. `Ids.PATTERN` is `^[a-z0-9_]{1,64}$`; PCRE `$` also matches before a trailing `\n`. Verified: `Ids.is_valid("base\n") == true`, `SaveData.is_valid_id("mesa\n") == true`, and `SaveData.from_dictionary({"owned_furniture": ["mesa\n"]})` keeps the entry; `WishBubble.ART_PATH_PATTERN` accepts `…/ball.png\n`. Not a directory escape (the `ResourceLoader.exists` that follows fails), but a tampered save can carry a newline-suffixed id and the "single owner" is wrong against its own spec. `test_the_contract_is_the_conventions_pattern` asserts the `^…$` string under a message saying "CONVENTIONS.md §4 is the source" — it passes while the source says otherwise; no test feeds a trailing newline.
   **Fix:** `\A…\z` in `Ids` and the art-path pattern; add `"mesa\n"` to `test_invalid_ids_are_refused` and a traversal+newline case for `show_wish`. Note SaveData previously required `{2,32}`; it now accepts `{1,64}` — confirm that widening is intended (ADR-005) and say so in BUG-008.

2. `game/tests/helpers/geometry_oracle.gd:133,183` — **Group checks are silent no-ops when the group is empty, so the oracle can still be vacuous per scene.** `_audit_rig` returns on no `rig` nodes; `_audit_edge_anchored` returns on no `ui_bottom`/`ui_top_right` nodes; spec keys that are omitted skip their checks. A builder that forgets `add_to_group("ui_bottom", true)` (nine more scenes are coming) passes with nothing asserted. The oracle also never audits the scene root's own rect (only the background, which inherits it). The anti-vacuity claim is true for what the new tests exercise (I confirmed the oversized-background, wrong-feet and floating-bar tests fail for real implementations), but not for a scene that opts out by omission.
   **Fix:** let the spec declare `required_groups` (`["rig","ui_bottom","ui_top_right"]` for care rooms) and emit a finding when one is empty; assert `root.get_global_rect() == canvas` directly.

3. `specs/verifications/FIX-e01-e02-2026-11-04.md:22-26`, `specs/adr/ADR-008-edge-anchored-responsive-composition.md:55-56`, `specs/bugs/BUG-002-expand-anchoring.md:34` — **Documentation overclaims.** The 4:3 "rig height ratio 0.574" rows and ADR-008's "The 4:3 canvas now composes: rig 0.574 of the height" present box geometry as the product requirement (see must-fix 1). FIX also lists "Coverage gaps … all closed" while the rig-visual gap is open. **Fix:** after must-fix 1, re-measure and rewrite those rows, label them "box" vs "painted", and correct the test name.

4. `game/tests/integration/test_preflight_guard.gd:70-85` — **Source-grep tests for BUG-011 verify strings, not behaviour.** `source.contains('"res://tools"')` is satisfied by a comment or a dead constant; `contains("game/tools")` likewise.
