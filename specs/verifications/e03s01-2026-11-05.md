## Behaviour proven

- RED came first: against a contract stub with empty handlers, 29 of the then 36 tests failed.
- A consumed food ignores a full replay of the gesture: no signal, no movement.
- `state_id()` is already `CONSUMED` when `drag_ended` fires, so e03s03 can tell a bite from a miss.
- A held food that is freed or removed releases the lock. A removed one returns to `REST` at home and works again when re-added.
- Disabling a held food does not wedge the lock: the gesture still ends.
- 30 motion events write no diary lines. Start, drop and consume each write one line with an id-shaped `item`.

## Control (anti-vacuity)

16 mutations of `touch_draggable.gd` were applied one at a time (device filter, exit-tree release, index check, static lock, `enabled`, canvas transform, local conversion, grab offset, margin, modes, rest capture, lock after drop, watchdog, per-motion log, double `consumed`, hit box). **16/16 make the suite fail.** The mutation script is a session tool and is not committed.

Each test file also passes when run alone (19 and 18 tests), so neither depends on the other for the static lock.

## Defects found by the tests and gates

1. **Vacuous canvas-layer test:** the first mutation run left "global without canvas" alive, because the finger point was inside the target under both transforms. The point moved to the target's near edge and now only hits with the layer offset.
2. **Type gate rejected the bare `Log` global:** GUT resolved it but `type_gate.gd` runs before autoloads exist, so preflight L0b went red. The tests now use `/root/Log`, as `test_log.gd` does.
3. **Weak diary test:** the consume test read only the last line. It now reads both lines from the diary file.

## Deviations recorded

- **Files beyond the story's list:** the single test file reached 597 lines and failed the audit limit of 300, so it became two test files plus `touch_draggable_test_case.gd`. All three are test-only.
- **One commit:** develop-tdd asks for separate RED and GREEN commits; this task's brief requires one commit. RED evidence is the stub run above, so `verify-tdd-red-commit.sh` does not apply (and is not vendored here).
- **Not run because not vendored in this repository:** `check-blind-spots.sh`, `completeness-critic.sh`, `verify-adversarial.sh`. `specs/verifications/e03s01-verify.yaml` and the `state.yaml` handoff were not written: this report is the requested evidence and `state.yaml` belongs to the orchestrator.
- **Beyond the literal AC, needed by it:** `_exit_tree` also returns a held food to `REST` at home and emits `drag_ended`, so a re-added node is not stuck and listeners can clear their state. `enabled` gates only the press.
- **Target hit test:** the target rect is computed in canvas space, not with `get_global_rect()`, so finger and target share a space inside a `CanvasLayer`. Without a layer or rotation the result is the same.

## Not verified

- **Real GUI dispatch and a real device:** headless Godot does not dispatch GUI input, so these tests call `_gui_input` with converted events. The windowed run, including whether a real mouse double-fires, is e03s03 AC 15.
- **Known limit:** a cancelled touch (`canceled == true`, for example a system gesture) is treated as a release, so it can consume a food if the finger was on the target. The lock is still released. No criterion covers it.
