# Post-epic review — e10 (friends, minigames, album)

**Epic:** `e10-friends-minigames-and-album-scenes` · **Date:** 2026-11-07 · **Verdict:** PASS
**Scope reviewed:** the whole e10 diff from `987056e` to `911e874` (four scenes, `FriendCatalog`,
`PuzzlePiece`, `CatchItem`, `PoiTable`, the star mutators, `ADR-012`).

This pass exists because e07, e08 and e09 each had one and e10/e11 did not: the dual-blind
`REVIEW-e11` covered the release harness, and nothing reviewed the four new scenes.

## Method

Read the diff, then attack it with the gates built by e11s01 — `INV-01` (save model), `INV-04`
(economy tables), `INV-05` (diary vocabulary), `INV-06` (FSM tables), `INV-07` (scene contracts),
`INV-09` (size bars) — plus the full suite. Every finding below is anchored to a test or to a
mechanical check, not to taste.

## Findings

| # | Sev | Finding | Status |
|---|---|---|---|
| 1 | medium | `AlbumScene` hardcoded the star cap `5` twice (`clampi(..., 0, 5)`, `range(5)`) while `SaveData.MAX_STARS` is the owner. Both numbers happen to be 5, so nothing was visibly broken — but raising the cap would have shown four lit points and one slot that can never light (the BUG-008 divergent-contract class) | **fixed** — both read `SaveData.MAX_STARS`; `test_every_card_renders_exactly_max_stars_slots` and `test_lighting_every_star_slot_leaves_none_dark` pin it |
| 2 | medium | `EconomyData.minigame_coins` had **no gate**. `FriendCatalog.coins_of` pays `0` for a friend missing from the table, silently, so a thirteenth friend added without a payout would win with an empty reward — the same shape as BUG-058, opposite direction | **gated** — `INV-04` now asserts the table covers `FriendCatalog.FRIEND_IDS` exactly, every payout ≥ 1, and that an unknown id pays 0 and never negative |
| 3 | low | `_reward_paid` is per scene instance, so `REWARD -> INTRO` (Replay) pays again. Verified against `e10s01`'s contract: replay *is* the earn loop, so this is the design, not a defect | no change; recorded so a future review does not "fix" it |
| 4 | low | `pinguim_jogo` grants a star only at `_catches >= STAR_TARGET` (6) while the duck and bear grant one per win. Checked against `e10s03` §2: the threshold is contractual ("effort pays, the star is mastery") | no change; the asymmetry is specified |
| 5 | info | `FurnitureLedger` and `PoiTable` are new modules with no test that names them directly; their behaviour is exercised through `ProgressManager` and `VilaScene` (`COVERAGE_MAP_LATEST.md` records them as indirect) | accepted, documented |

## Verified clean (not assumed)

- **Scene contract:** all four scenes are `Control` roots that fill the canvas, cover the
  background, declare `background`/`rig`/`hit_target` groups, and carry no word on screen — the
  static `INV-07` scan covers them without a per-scene test being written for it.
- **FSM tables:** `DuckDanceScene`'s four states are closed, every edge target is declared, and
  `WAITING` has a 120 s dwell so a shy child is never timed out (`INV-06`).
- **Touch:** every pad/card is a `TapButton`, so the `device == -1` echo filter is inherited, and
  each scene test drives it through `TouchSim` with the echo on.
- **Economy:** stars are clamped at the save model *and* at the read (`stars_of`,
  `SaveData._clean_stars`), and a capped friend refuses rather than overflows.
- **Size bars:** `pato_danca` 281, `urso_puzzle` 296, `pinguim_jogo` 297, `album` 163 — all under
  the 300-line ceiling, which `INV-09` now enforces for every file.

## Outcome

No high-severity defect. One real latent defect fixed (findings 1) and one missing gate closed
(finding 2). Two behaviours that read like bugs were checked against their contracts and are
correct (findings 3, 4).
