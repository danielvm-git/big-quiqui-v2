## Summary

The branch is not releasable. The shipped probe paths are broadly playable and the selected tests pass, but the validation perimeter contradicts the feature contract: `count_n` is implemented yet rejected, multiple zero-exit definitions are accepted, dress data can write unowned or category-invalid items, and the advertised completeness gate does not check several fields it claims to enforce. Four additional review-bar and test-integrity defects weaken the evidence.

## Findings

### B1 — must-fix — The loader rejects the required `count_n` tap mode

**File:** `game/scripts/core/step_params.gd:16`

**Evidence:** `T21_MODES` permits `any`, `single`, and `toggle`, while the story and primitive define `any`, `count_n`, and `toggle`. `TapPrimitive.progress()` implements `count_n` at `game/scripts/components/tap_primitive.gd:31`, but any real `SceneDef` using it is rejected as `bad_mode`. The passing `count_n` tests instantiate the template directly and bypass `SceneDefLoader`, so they cannot expose this integration failure.

**Suggested fix:** Replace `single` with `count_n` and add a loader-level test that validates and mounts a `count_n` def.

### B2 — must-fix — Malformed definitions can create steps with no exit

**File:** `game/scripts/core/step_params.gd:27`

**Evidence:** Template-specific validation does not require non-empty `item_ids` for `t21`, `t34`, `t45`, `t50`, or `t51`. For example, `t50_lanes` accepts an empty item set, `Spawner.tick()` then never emits anything (`game/scripts/components/spawner.gd:30`), and progress remains zero (`game/scripts/templates/t50_lanes.gd:90`). Map positions are checked only for finiteness at `step_params.gd:100`; a destination outside `world_size` also validates but cannot be reached. Existing tests validate shipped defs and numeric bounds, not these no-exit cases.

**Suggested fix:** Add per-template required-field/cardinality checks, reject map points outside the declared world, and add loader-level negative tests for each zero-exit shape.

### B3 — must-fix — Dress data bypasses the threat model's ownership control

**File:** `game/scripts/templates/t45_dress_decorate.gd:60`

**Evidence:** `snap()` checks only the id grammar, artwork, and a def-provided slot before calling `ProgressManager.equip`. `equip()` at `game/scripts/autoloads/progress_manager.gd:140` also checks only grammar and writes the value. A tampered def can therefore save any pictured id (for example a food item) into any syntactically valid slot without ownership or category validation. This contradicts the e13 threat model's explicit “ownership checked before any save call” mitigation.

**Suggested fix:** Validate slot/category compatibility and ownership in the save-owning service before mutation; add a test with a valid, pictured, unowned/wrong-category id and assert zero writes.

### B4 — must-fix — The wave completeness gate does not enforce its stated contract

**File:** `game/tests/helpers/template_table_gate.gd:7`

**Evidence:** The gate defines indexes only for id, status, scene, test, and scene count. `problems()` at line 31 checks catalog membership, script/test existence, consuming def, and scope arithmetic, but never checks that the rule, parameters, or evidence cells exist or are non-empty. `SC-e13s09-P1-03` claims the gate fails when a template lacks a rule, test, or consumer; its anti-vacuity tests remove a row or swap a scene, but never blank a rule. A row with empty rule/parameters/evidence passes.

**Suggested fix:** Parse and validate every required column, reject duplicate/malformed rows, and add injection tests that blank rule, parameters, test, consumer, and evidence independently.

### B5 — should-fix — The test plan still claims four skipped scenarios are implemented

**File:** `specs/tech-architecture/e13-TEST_PLAN_LATEST.md:53`

**Evidence:** The plan lists `SC-e13s07-P1-01` through `P2-01` as expected tests and still totals 48 scenarios. The final task file explicitly says not to implement either template or its tests (`e13s07-tasks.yaml:11-48`), and no corresponding test files exist. The story itself still advertises a playable scene. This makes scenario coverage and status reporting false after the evidence-driven skip.

**Suggested fix:** Mark the scenarios withdrawn/superseded by the skip, update totals and playable target, and make the capsule consistently describe the accepted decision.

### B6 — should-fix — New state machines omit the declared dwell table

**File:** `game/scripts/components/pan_primitive.gd:25`

**Evidence:** Both Pan and Steer construct `Fsm` with only the initial state and legal edges (`steer_primitive.gd:19`). Project conventions require `legal_edges` and `max_dwell_sec` to be declared upfront for every state machine. No explicit empty dwell table is supplied.

**Suggested fix:** Declare the dwell table (empty if these child-owned gestures intentionally have no deadline), pass it to `Fsm.new`, and test the intended no-timeout policy.

### B7 — should-fix — Two changed functions exceed the 20-line bar

**File:** `game/tests/helpers/template_table_gate.gd:31`

**Evidence:** `TemplateTableGate.problems()` has 23 non-comment body lines. `_mount()` in `game/tests/unit/test_t34_rub_reveal.gd:48` has 22. Both files are new/changed and therefore subject to the explicit 20-line maximum.

**Suggested fix:** Extract row validation/catalog reconciliation from `problems()` and context construction from `_mount()`.

### B8 — should-fix — The aspect test can pass with inaccessible targets

**File:** `game/tests/integration/test_template_aspects.gd:27`

**Evidence:** The test checks every discovered target's size, but increments `seen` only for targets enclosed by the viewport and then asserts merely `seen > 0` at line 37. A def with one visible target and every other required target off-screen passes despite the test name and the plan's “every tap target” claim.

**Suggested fix:** Assert reachability for each required target, with explicit pan/scroll handling for map and strip content; add an injected off-screen target to prove the gate fails.
