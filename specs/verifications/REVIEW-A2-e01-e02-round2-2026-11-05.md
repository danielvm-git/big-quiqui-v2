## Findings

### must-fix
1. `game/scripts/components/quiqui_rig.gd:232-244` (`get_visual_global_rect`) and every doc that calls its result "the painted
   character" (`DESIGN.md:33-34`, `ADR-008:43,53`, `FIX-e01-e02:23-34`, `BUG-013`, `BUG-014:61-62`) —
   `get_visual_global_rect` returns `texture.get_size() * scale`, the 1024×1024 frame. The PNGs have large transparent margins.
   I measured `Image.get_used_rect()` on `game/assets/art/quiqui/*.png`: for `quiqui_base`, `_rindo`, `_pijama`, `_surpresa` and others
   the opaque pixels start at y=75 and are 868 px tall. That is **0.848 of the frame**, with 75 px empty above and 81 px empty below.
   So the visible height is 0.575 × 0.848 ≈ **0.49** of the canvas on all six measured cases. The visible feet sit about 0.046 above
   the stated line (casa ≈ 0.734, titulo ≈ 0.880).
   Failure caused: the cycle exists to remove the "measured the container, not the character" defect, and the same defect
   survives one level down. The oracle passes a rig whose child-visible height is 49 %, and the records state "painted character
   0.575", which is untrue of what the child sees. Round 1's 0.418 was also a frame measurement, so the author
   reproduced the reviewers' method; the method is wrong, and the 16:9 "approved" design was 0.49 too.
   Fix: either (a) measure the opaque rect (`Image.get_used_rect()` cached per expression, or a per-art `visible_rect` constant) in
   `get_visual_global_rect` / the oracle and rescale or re-anchor so it lands in 0.55–0.65, with the feet line on the opaque bottom;
   or (b) if the frame is deliberately the design unit, amend `DESIGN.md` §3 and ADR-008 to say
   "art frame, including transparent margin" and drop every "painted character" claim. Add a test that fails for a padded texture.

### consider
1. `quiqui_rig.gd:293-300, 311` — `_apply_expression` calls `_fit_box_to_art()` *before* `_update_layout()` updates
   `_art_aspect`. If a non-square expression texture is ever swapped in, the box is fitted to the previous art's aspect until the next resize.
   All shipped art is 1024², so this is latent. Swap the order, or read the aspect from the texture inside `_fit_box_to_art`.
2. `quiqui_rig.gd:1-346` — the file is 346 lines (guideline 300). `FIX-e01-e02:95` still says "310 lines … accepted debt". The record is stale and the
   debt grew by 36 lines in this fix. Smells: *Large Class* (layout, blink/breath animation, expression/outfit state,
   hit area in one `Control`) and *Divergent Change* (this fix touched layout only, but animation code lives in the same file).
3. The tap surface is the frame (`quiqui_rig.gd` box = texture), so the 75 px of transparent margin above the head (8 % of the box) still takes taps.
   The oracle's 3 % dead-space limit checks the box against the frame and cannot see it. Resolved by must-fix 1(a).
4. `quiqui_rig.gd:_fit_box_to_art` rewrites `offset_left/right` inside `NOTIFICATION_RESIZED`. I checked termination: the `BOX_FIT_EPSILON` guard means a second
   pass is a no-op, and mutation (see below) shows no loop. Setting offsets in the resize notification is still re-entrant;
   a comment stating the invariant ("idempotent, converges in one pass") would help the next editor. The guard only fires for
   `anchor_left == anchor_right == 0.5`; other anchors silently skip, and only the oracle's dead-space check would notice.
5. `geometry_oracle.gd:BOX_DEAD_SPACE_TOLERANCE` (3 % of canvas height) is a magic number tied to nothing in `DESIGN.md`.
