## Findings

### must-fix

1. **`game/scenes/casa.tscn:194-204` (with `game/scripts/scenes/casa.gd:88-90`) — the wish bubble now covers QuiQui's head and face on both 4:3 canvases; this change introduces it, and `ADR-008:38` asserts the opposite.**
   The bubble is pinned with *absolute* offsets to the feet line: `anchor_top = anchor_bottom = 0.78`, `offset_top = -812`, height `220`. Its visible art (frame bbox `98,126 → 927,922` of 1024, scaled into 220 px) occupies `bubble.y + 27 … bubble.y + 198`.

   | Canvas | painted character (post-fix) | bubble art | overlap |
   |---|---|---|---|
   | 1920×1080 | 217.98 … 842 | 57 … 228 | 10 px (hair; **unchanged**, bubble was tuned for this) |
   | 1920×1440 | 295.9 … 1123 (827 tall) | 338 … 509 | **213 px = 26 % of her painted height** |
   | 2048×1536 | 315.5 … 1198 (882 tall) | 413 … 584 | **269 px = 30 %** |

   Pre-fix, on the same canvases, the painted character started at `482.6` / `557.3`, so the overlap was **27 / 49 px (3–8 %, hair only)**. Making her 33 % taller on 4:3 moved her head up through a bubble whose offset was hard-coded for a 620 px character. `casa.gd` shows the bubble *together with* `set_expression("carente")` — i.e. exactly when the sad face is the thing the child must read, and she is a pre-reading 4–7 year-old whose only feedback channel is her face.
   `specs/adr/ADR-008-…:38` — “`WishBubble`: pinned to the feet line, so it stays above QuiQui's head **on every aspect**” — is false on the primary device, and nothing asserts it (`test_casa_scene.gd` only checks `is_showing()` / `wish_id()`; `GeometryOracle` has no bubble check).
   *Suggested fix:* make the bubble ratio-driven off the character's top instead of an 812 px absolute — e.g. in `build_casa_scene.gd` pin it at `anchor_top = anchor_bottom = FEET_RATIO - RIG_HEIGHT_RATIO` with `offset_top = -228`, `offset_bottom = -8`, and add the assertion `rig.get_visual_global_rect().position.y >= bubble.get_global_rect().end.y` on both aspects (or a `bubble_clears_head` check in `GeometryOracle`).

### should-fix

1. **`game/scripts/components/quiqui_rig.gd:260-275` — `opaque_rect()` still fails **open**: “Falls back to the whole frame when the image cannot be read.”** That is the exact silent fall back the oracle was just taught to refuse. Simulated by forcing the `get_image()` branch off: the suite goes **157/158** and the only failure is one unit assertion (`the art frame carries transparent margin`) — every oracle and scene test stays green while the layout scales the art on a 1024² frame, i.e. the child sees **0.4866** of the canvas (measured, same as the pre-fix bug) and the gate reports 0.574. Reachable today via `PlaceholderTexture2D` (`get_image() == null`, verified) and by any future art pipeline that strips image data; the shipped `CompressedTexture2D` (`vram_texture=false`, `compress/mode=0`) does return the image headless, so this is latent, not live. Fix: on a failed read return `Rect2()` (or set a `_measurable = false` flag) so `get_visual_global_rect()` is empty and the oracle says `no painted geometry`; the same fallback also shrinks the art in `_update_layout:352-358`.
2. **`specs/verifications/FIX-e01-e02-2026-11-04.md:25-30`, `specs/adr/ADR-008-…:53`, `specs/bugs/BUG-013-…:70`, `BUG-014` §Resolution 4 — the published “painted height” column is an idle-breathing phase, not a design value.** At rest painted **equals** the box (`881.777709` vs `881.777709`); the table's `0.575 / 0.578` is `0.574 × pivot.scale.y` with the un-stepped `_process` still running (`BREATH_Y = 0.022`, envelope measured over one period: **0.5614 … 0.5867**). So ADR-008's “**painted** character 0.575 of the height (box 0.574)” states a difference that cannot exist structurally, and the probe's output depends on how many `_process` frames elapsed — a number a reviewer cannot reproduce. Fix: set `manual_step = true` in `measure_hero_scale.gd` (or report the box/painted rest value plus the breathing envelope).

### consider

1. **`game/tests/helpers/geometry_oracle.gd:195` — `_painted_rect` is duck-typed**, so the oracle trusts the rig's self-report. After this fix the box and the painted rect coincide by construction, which means *no* assertion in the suite can distinguish “measured the art” from “measured the box”: reverting `get_visual_global_rect()` to `return get_global_rect()` leaves **158/158 green** (verified). That is not shippable-bug-equivalent today (the layout keeps the invariant, and losing the invariant alone fails 30 asserts), but the test named `test_the_character_is_measured_on_its_opaque_pixels` does not defend the property its name claims; consider pinning it against the known margin (`painted.size.y ≈ 868/1024 × frame_height`).
2. **No test covers a `rig`-group node that is a `Node2D` or a plain `Control` *inside a real scene*** — the behaviour is correct (verified), the regression guard is only the synthetic `PaintedBox`/`Control` fixtures.
3. **`geometry_oracle.gd:204-212` checks only vertical dead space.** A padded / non-square expression swapped at runtime keeps height and feet (verified) but overflows horizontally (`painted = 1045×882` around a `418` wide box) with no finding; on a real scene that overflow would silently cover a door column. A `canvas.encloses(painted)` check (or `painted.size.x <= box.size.x * 1.2`) would close it.
4. **`quiqui_rig.gd:73,260-274` — `_opaque` is keyed by `texture.get_instance_id()`**, which Godot recycles after free; the cache holds no reference, so a reused id would silently return a stale rect. Textures here are loader-cached, so it cannot fire today; a `WeakRef`-free alternative is to cache on the `Texture2D` key itself (Dictionary accepts objects as keys).
5. **`test_geometry_oracle.gd:...test_a_scene_that_forgets_a_declared_group_is_caught` asserts an exact finding count (`3`)**, which breaks whenever a fourth `required_group` is added or another root-level check appears.
