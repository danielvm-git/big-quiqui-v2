## Findings

### F1 — HIGH — Both scene roots are packed at 2× the canvas; the background is a 2× zoom crop

`game/tools/build_titulo_scene.gd:21-22`, `game/tools/build_casa_scene.gd:30-31` do
`set_anchors_preset(PRESET_FULL_RECT)` **then** `root.size = Vector2(1920, 1080)`. Godot's
`set_anchors_preset` preserves the current rect by rewriting offsets, so the packed scene
(`casa.tscn:13-18`, `titulo.tscn:13-18`) contains `anchor_right/bottom = 1.0` **with**
`offset_right = 1920, offset_bottom = 1080` → rect = parent + 1920/+1080.

Measured (headless probe, `SubViewport` + 2 frames, deleted after use):

| Canvas | `Casa` root rect | `Background` rect |
|---|---|---|
| 1920×1080 (16:9) | 3840×2160 | 3840×2160 |
| 1920×1440 (4:3 expanded) | 3840×2520 | 3840×2520 |
| 2048×1536 (raw 4:3) | 3968×2616 | 3968×2616 |

Consequence: `Background` is a full-rect child of a doubled root, so `STRETCH_KEEP_ASPECT_COVERED`
scales `bg_home.jpg`/`bg_title.jpg` to 3840×2160 — the visible 1920×1080 region shows only the
**top-left quadrant of the art at 2× zoom**, not the intended full-bleed composition. The rig and
doors keep correct canvas coordinates, so the scene looks "mostly right" and the crop is easy to
mistake for art.

Fix: `set_anchors_and_offsets_preset(Control.PRESET_FULL_RECT)` and drop the `size` assignment
(verified: yields exactly 1920×1440 in the 4:3 virtual canvas); regenerate both `.tscn`; then close
**F18** so the regression cannot come back.

### F2 — HIGH — Interactive UI is not anchored to the expanded 4:3 canvas

Composition is fixed pixel offsets in a 1920×1080 coordinate space (`build_casa_scene.gd:47-80`),
no `SafeStage`, no `MarginContainer`. `DESIGN.md:27-31` requires edge anchoring or a centered
`SafeStage` (1680×960) and feet at **78 %** of stage height; ADR-002 repeats "centered `SafeStage`
container".

Measured on the 4:3 virtual canvas 1920×1440:

| Node | end_y_ratio | Design |
|---|---|---|
| `QuiQuiRig` (620 px) | 0.58 | feet at 0.78 |
| rig height / canvas | 0.43 | 0.55–0.65 |
| `CareDotsBar` | 0.72, bottom gap **396 px** | bottom-anchored, 36 px inset |
| `DoorVILA` | 0.60 | inside stage |

So on the primary target (iPad 4:3) QuiQui floats at 58 % with a 396 px empty band below the dots.
`e02s03-2026-11-04.md:62` records this as an accepted trade-off, but no ADR/exception carries it and
the requirement text is unchanged — spec/implementation divergence with no owner.

Fix: introduce `SafeStage` (full-rect anchored, 1680×960 centered) inside both scenes and anchor the
rig/dots/doors to it, or convert the door columns and HUD to anchor-relative offsets; then extend
`GeometryOracle` with aspect-aware assertions (rig height ratio, feet ratio, bottom safe gap).

### F3 — MEDIUM — `abandon_step()` logs the step it just left as `idle`

`care_loop_manager.gd:74-80`: `fsm.transition_to(STATE_IDLE)` runs first, then
`_emit("care.abandon", {"step": fsm.state.to_lower()})` reads the **new** state. Every abandon event
records `step=idle`, so the R-mitigation in the e02 threat model ("parent can tell which care steps
happened") is defeated for exactly the case it was written for. No test asserts the payload.

### F4 — MEDIUM — `fsm.dwell_timeout` logs `limit_sec` in milliseconds

`fsm.gd:105`: `{"state": ..., "limit_sec": int(limit * 1000)}`. A 2.0 s limit is emitted as
`limit_sec=2000`. Rename the key to `limit_ms` (or divide by 1000). Untested payload.

### F5 — MEDIUM — Every human-readable `msg` is redacted away

`log.gd:160-171` runs `is_safe_id()` on `msg`, whose pattern `^[a-z0-9_.:/-]{1,64}$` rejects spaces,
so `event("x", {"msg": "hora do banho"})` stores `<redacted>`. The external auditor explicitly
exempts prose there (`scripts/log_tool.py:37` `MSG_KEYS`, `:191`), i.e. the writer is stricter than
the contract it is validated against. The only field able to carry a PT-BR diagnostic is unusable.
`test_log.gd` only feeds id-shaped `msg` values, so it never notices.

### F6 — MEDIUM — A hidden `WishBubble` reports scale 1.0 but keeps the last pulse on screen

`wish_bubble.gd:53`: the hidden branch sets `_pulse_scale = 1.0` without resetting `_visual.scale`,
so `pulse_scale()` (the test observable) and the actual transform disagree after `hide_wish()`
mid-pulse. Set `_visual.scale = Vector2.ONE` there and assert `_visual.scale` in
`test_pulse_only_moves_while_shown_and_is_deterministic`.

### F7 — MEDIUM — `QuiQuiRig.reset()` leaves the previous outfit visible

`quiqui_rig.gd:225-235` clears `outfit_id` but neither hides nor untextures `outfit`, so an outfit
survives a reset while the model says none is equipped. `set_outfit("")` (the correct path) is not
used. Any future `TestReset`-driven reuse inherits the wrong art.

### F8 — MEDIUM — Tickets share `SaveData.MAX_COINS`; cycle counter unclamped

`progress_manager.gd:119` clamps tickets with `MAX_COINS` (999 999) — no ticket-specific cap, and the
constant name lies about its use. `complete_cycle()` (`:123-128`) increments `completed_cycles`
without a ceiling and emits `progress_changed` three times (once per mutator plus once itself).

### F9 — MEDIUM — Three divergent id contracts

`SaveData.ID_PATTERN` = `^[a-z0-9_]{2,32}$`, `QuiQuiRig.ID_PATTERN` = the same literal again,
`Log._id_re` = `^[a-z0-9_.:/-]{1,64}$`, while `CONVENTIONS.md:76` mandates
`\A[a-z0-9_]{1,64}\z`. A save id that is valid for Log is invalid for SaveData and vice versa.
Extract one `Ids` helper (pattern + `is_valid`) and point all three at it.

### F10 — LOW — `complete_step("IDLE")` silently starts FEED

`care_loop_manager.gd:135-142`: `_successor(IDLE)` returns `FEED` (the first non-IDLE edge), so
"complete the IDLE step" begins the cycle. `_successor` should return `""` for `IDLE`; only
`begin_step` may enter FEED.

### F11 — LOW — The Vila door is permanently dimmed

`casa.gd:134-139` dims every door whose key ≠ `next`, and `next` is only ever one of the five care
steps — never `"VILA"`. The recycling door therefore always renders at 0.72 alpha while remaining
fully tappable: a disabled look on an enabled control (and a contrast risk for the 4–7 range).

### F12 — LOW — Duplication (G5)

- Log bridge `_emit`/`_log` in 10 files (5 lines each).
- Squash spring (`SQUASH_STEPS` + `SQUASH_STEP_SEC` + the ~20-line stepper) copy-pasted in
  `tap_button.gd` and `quiqui_rig.gd`; the constant comment even says "same spring as TapButton".
- The two scene builders share ~55 lines (`_set_owner_recursive`, pack/save/error/quit, `_count`).
- The five care-step names are string literals in `CareLoopManager`, `casa.gd`, `build_casa_scene.gd`.

### F13 — LOW — Speculative / dead state

`QuiQuiRig.body` is created and never textured (no `set_body`), and `headwear`/`neck`/`glasses` have
layers and z-constants but no API (deferred to e10 per the file comment). `CareLoopManager.test_mode`
is written by `set_test_mode()` and read by nothing.

### F14 — LOW — The rig never re-lays out on resize

`QuiQuiRig` computes `pivot.position` in `_build_rig()` and `_update_layout()` only when an
expression changes; there is no `NOTIFICATION_RESIZED` hook, so any future responsive rig keeps the
first frame's scale/feet position. Not reachable today (both scenes are fixed-size), but it is the
one component ADR-002 exists for.

### F15 — LOW — Gate blind spots in tooling

`type_gate.gd:14-19` scans `res://scripts res://components res://scenes res://tests` — the middle two
do not exist and `res://tools` (both builders, `type_gate.gd` itself) is never compiled under strict
typing. `scripts/trace-stories.sh` likewise only walks `game/scripts` and `game/tests`.

### F16 — LOW — Managers dereference internals before `_ready`

`care_loop_manager.gd:89` (`fsm.state`) and `audio_manager.gd:185` (`_voice.stream`) crash if called
before their own `_ready` (reproduced when a `SceneTree` script instantiates `casa.tscn` before
autoload frames). Autoload ordering hides it in production, but threat T-E02-03 asked for exactly
this guard and no test covers it.

### F17 — LOW — `show_wish()` validates a path by prefix/suffix only

`wish_bubble.gd:62-65` accepts `res://assets/art/../../x.png` (and any string ending in `.png` under
that prefix). Local-only art, but the e02 threat model claims "ids validated by pattern before path
construction". Reuse the id pattern (F9) and build the path from the id.

### F18 — LOW — Anti-vacuity gap in `GeometryOracle`

`geometry_oracle.gd:60-63` asserts only `rect` **covers** the canvas (±1 px), never that it matches
it. That single `>`/`<` asymmetry is what let **F1** ship green, and it is the same failure class as
the Zero-Test Guard the project already hardened against (`test_preflight_guard.gd`). Add
`abs(rect.size - canvas.size) <= COVER_TOLERANCE` for any `background` node plus a regression test
that mounts a scene whose root is deliberately oversized.
