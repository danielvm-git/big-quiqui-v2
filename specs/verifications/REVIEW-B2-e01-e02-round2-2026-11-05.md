## Findings

### must-fix

**1. `game/tests/helpers/geometry_oracle.gd:173,176,189` — the gate fails *open* when the rig cannot report a
painted rect, so it can still measure the box, which is the exact defect BUG-013 exists to remove.**

```gdscript
var measured: Rect2 = painted if painted.has_area() else box   # :173
if painted.has_area():                                        # :176
    _audit_rig_box_is_the_character(control, box, painted, canvas)
...
if control == null or not control.has_method("get_visual_global_rect"):   # :189
    return Rect2()
```

A rig that cannot produce painted geometry silently reverts to the box measurement and to *skipping* the
dead-space check, with no finding. I mounted the shipped scene and attacked it:

- **Real `casa.tscn` at 2048×1536, `Pivot/Expression` hidden** (what a missing/renamed art file produces:
  `_load_art` returns `null`, no sprite has a texture): `get_visual_global_rect()` → `Rect2()`, and
  `GeometryOracle.audit(scene, 2048×1536, spec)` returned **`[]` — clean**, including the height assertion.
  The suite happens to catch this via the separate `assert_true(scene.rig.get_visual_global_rect().has_area())`
  (`test_casa_scene.gd:69`), but the layout oracle itself does not, and ADR-008 advertises the oracle as
  the mechanical gate.
- **The old broken geometry, with a rig node that has no `get_visual_global_rect`**: a plain `Control` in
  group `rig` at `Rect2(704, 316, 640, 882)` on 2048×1536 — i.e. exactly the 640-px-wide box that painted the
  character at 0.418 — produces **no rig finding**. The oracle's own positive control
  (`test_a_correctly_anchored_rig_passes_the_care_room_spec`) is literally that geometry; nothing distinguishes
  it from the fixed one.
- **A `Node2D` in group `rig`**: `var control: Control = node as Control` → `null` → `continue` (`:169`), and
  `_audit_required_groups` (`:87`) sees the group as non-empty and is satisfied. The entire rig contract
  disappears while the spec check reports the group as declared.

Why it matters: BUG-013 was "the gate proved the box". Nine more scenes (e03–e10) will be written against this
oracle, and a rig that is not a `QuiQuiRig` — or a scene whose art fails to load — reproduces round 1 with a
green gate. A gate may not degrade silently; "cannot measure" must be a finding.

Suggested fix (two lines): in `_audit_rig`, emit a finding when the node is not a `Control`, and when
`painted.has_area()` is false emit `"rig %s exposes no painted geometry"` instead of falling back to `box`
(make the box the *second* assertion, as the round-1 fix plan said, not the fallback).

**2. `DESIGN.md:36` — the px reading that round-1 reviewer B required be corrected is still there, and it is
false on the canvas the game targets.**

> QuiQui occupies **`55%–65%` of viewport height** (`~600–700 px` tall) […]

Reviewer B's must-fix 2 stated the two readings "cannot both hold" and required that, if the ratio reading won,
the `600–700 px` line be corrected. The fix took the ratio reading (painted 0.575) and left the px reading in
place. On the iPad canvas the character is 0.575 × 1440 logical = **828 px** (883 px at 2048×1536 physical),
not 600–700; `~600–700 px` is true only on 1920×1080 (621 px). The probe's own row makes it visible:
`casa 1920x1440 painted_h=0.575` = 828 px.

Why it matters: this is the BUG-014 defect recurring in the document BUG-014 fixes — a number that is true of
one canvas presented as the rule. An e03 builder reading §3 gets an absolute px budget that contradicts the
ratio gate.

Suggested fix: `(~620 px on the 16:9 canvas; the **ratio**, not the px, is the contract on every canvas)`.

**3. `specs/bugs/BUG-013-hero-scale-measures-box-not-art.md:65` — claims `WishBubble.ART_PATH_PATTERN` is now
`\A…\z` with trailing-newline tests. Neither is true.**

> Deferred reviewer items closed in the same commit: `Ids.PATTERN` and `WishBubble.ART_PATH_PATTERN` are
> `\A…\z` with trailing-newline tests […]

`game/scripts/components/wish_bubble.gd:20` is still
`"^res://assets/art/([a-z0-9_]+/)*[a-z0-9_]+\\.png$"`, unchanged in this commit, and no test feeds a
newline-suffixed art path (`test_wish_bubble.gd` gained only `test_reset_mid_pulse_returns_the_visual_to_rest`).
`Ids.PATTERN` (`ids.gd:12`) *was* changed and its test added — so half the sentence is true and half is a
fabricated closure, in the record that closes "records overclaim".

Why it matters: round-1 reviewer A should-fix 1 asked for both patterns; this record tells the reader both were
done. Functional impact is nil (`ResourceLoader.exists` rejects the newline path), so the defect is purely the
false record — which is the gate criterion for this cycle.

Suggested fix: either change `ART_PATH_PATTERN` to `\A…\z` and add the `"…png\n"` case to
`test_a_traversal_path_is_refused`, or delete `WishBubble.ART_PATH_PATTERN` from that sentence and record it as
deliberately deferred.

### should-fix

**4. `game/tests/helpers/geometry_oracle.gd:40,48` — `required_groups` was added as a mechanism but is not
declared in either spec, so the documented "pass the spec" path still opts out of the group checks.**

Round-1 reviewer A should-fix 2 asked for `required_groups` *in the spec*. The fix put it in a test-local
duplicate, `test_casa_scene.gd:194 _care_spec()`. `CARE_ROOM_SPEC` and `TITLE_SPEC` still declare only the
ratios, so `_audit_required_groups` (`:87`) no-ops for every caller that follows ADR-008's instruction the way
it is written, and `_audit_edge_anchored`/`_audit_rig` keep returning silently on an empty group. The title
scene has no `required_groups` test at all: drop `groups=["rig"]` from `titulo.tscn` and every oracle assertion
about the title rig disappears while `test_titulo_scene.gd:45` stays green. Fix: move
`["rig","ui_bottom","ui_top_right"]` into `CARE_ROOM_SPEC`, `["rig"]` into `TITLE_SPEC`, and delete the
test-local helper.

**5. `game/tests/unit/test_quiqui_rig.gd:174-177` — the designated test for the fit cannot fail for the property
its docstring names ("the box widens with the art" is not the requirement; *centred and on the floor* is).**

It asserts three size relations and one ratio; it never asserts `painted.end.y`, nor the painted x-centre. A rig
whose fit sets asymmetric offsets (`offset_left = 0.0`, `offset_right = wanted`) keeps `size.x == painted.size.x`
and `size.y == painted.size.y` exactly, so the test passes while the character sits half a box off-centre. The
shipped scenes are covered by the integration tests and by `_audit_rig`'s centre check (`:178`), so this is a
hole in the guard, not in the product. Fix: add
`assert_almost_eq(painted.get_center().x, mounted.size.x * 0.5 + mounted.global_position.x, 1.0)` and
`assert_almost_eq(painted.end.y, mounted.global_position.y + mounted.size.y, 1.0)`.

**6. `game/scripts/components/quiqui_rig.gd:230` — the docstring of the observable the whole gate now trusts says
"in rig-local coordinates"; the function returns global (canvas) coordinates.**

It uses `sprite.global_position` / `sprite.global_scale`, and `GeometryOracle` compares the result against the
canvas rect. The comment predates this commit, but this commit promotes the function to the contract, and a
maintainer reconciling the code to its comment would break the feet and centre assertions. Fix the comment.

### consider

7. **The gate measures a live animation, not the layout.** `get_visual_global_rect` includes the breathing
   transform, which is why the same code path reports 0.578 at 1920×1080 and 0.575 at 1920×1440 — that 0.003 is
   frame phase, not a canvas property, yet it is tabulated as one in `FIX-e01-e02` and `BUG-013:61`. Worse,
   `SquashSpring.STEPS[0].y == 0.88`: tap the rig and audit in the same frame and painted height is
   `0.574 × 0.88 = 0.505`, below `rig_height_min` — a future "tapping does not change the layout" test fails
   spuriously. Fix: set `manual_step = true` (or `reset()`) in the probe and before auditing, so the number is
   rest geometry; the records then say 0.574 everywhere, which is what the contract is.
8. **`_apply_expression` fits with a stale aspect.** `quiqui_rig.gd:305` calls `_fit_box_to_art()` before
   `_update_layout()` refreshes `_art_aspect` (`:315`), so the first pass uses the *previous* aspect. Square art
   makes this invisible today; non-square art leaves horizontal dead space for one pass, and
   `_audit_rig_box_is_the_character` (`:197`) only measures **vertical** dead space, so it would not be caught.
   Compute the aspect from the texture in `_fit_box_to_art`, and check both axes.
9. **The `.tscn` files and the builder are no longer the source of truth for the rig width.** `casa.tscn`
   still declares `offset_left = -320 / offset_right = 320`; the rendered width is 620 (16:9) or 882 (4:3),
   decided at runtime. Anything that reads the scene without running `_ready` (editor preview, a future
   geometry lint) sees the pre-fix numbers.
10. **Inherited, still open:** round-1 reviewer A should-fix 4 (`test_preflight_guard.gd:70-85` asserts on
    source strings). This commit did not touch it; it remains the only guard for the widened gates.

### Fowler smells

- **Data Clumps / Speculative Generality** — the layout contract is an untyped `Dictionary` with five optional
  keys, each of which silently skips its check when absent (`_audit_rig_height:222`, `_audit_rig_feet:209`).
  Must-fix 1 and should-fix 4 are both consequences of "absent means skip".
- **Duplicate Code / Divergent Change** — the 0.5/0.5 anchor column is encoded in `_fit_box_to_art:104`, both
  `.tscn` files, `test_quiqui_rig.gd:163`, and `test_geometry_oracle.gd:127`. Four places must agree for the fix
  to hold; BUG-013 is what happens when they do not.
- **Comment as deodorant** — `quiqui_rig.gd:230` (should-fix 6) and the "second assertion" wording in
  `BUG-013:59` describing what the code implements as a fallback.

## What looks right

- **The fix itself is correct.** Painted height 0.575–0.578 of the canvas on 16:9, 1920×1440 and 2048×1536,
  feet 0.780 (casa) / 0.926 (titulo) everywhere. I could not make it drift by re-anchoring, changing the canvas,
  or ordering `_ready` before layout — the `NOTIFICATION_RESIZED` path re-fits.
- **`_fit_box_to_art` terminates and stays centred.** The second pass trips the `BOX_FIT_EPSILON` guard, so the
  recursion depth is 2; measured painted centre x = 1023.98 on a 2048-wide canvas. No resize loop.
- **The guard is honest.** `_fit_box_to_art` only fits a centred `0.5/0.5` column, and when it bails (stretched
  anchors) the old width-limited fit returns — which the height assertion then catches (640/1024 → 0.416). No
  silent pass on that path.
- **Mouth proximity is preserved.** `size.y - art.y*factor*0.62` is the same point relative to the art before and
  after, because `size.y == art.y*factor` once fitted; `test_the_mouth_zone_lives_inside_the_visible_art` passes.
- **The tap surface is genuinely fixed** (round-1 reviewer B should-fix 3): the box now *is* the art on both
  scenes, so the 185–240 px of blank affection surface above her head on 4:3 is gone. Doors, bubble, dots and
  HUD are later siblings and still win input.
- **`Ids.PATTERN` → `\A…\z` is right**, `search()` + `\A…\z` is a full match, and the newline cases cover both
  `Ids.is_valid` and `SaveData.from_dictionary`.
- **`Log.event()` clearing `last_line` before the `_file == null` return** is the correct place; the claim in
  BUG-013 matches the code.
- **Two of the four new oracle tests are not tautological**: I confirmed `test_a_character_that_paints_smaller_than_its_box_is_caught`
  and `test_an_oversized_scene_root_is_caught` fail for real broken implementations, and the painted-height
  integration tests fail if the box is fitted but the art is not.
- **Conventions:** strict typing passes `type_gate` over `game/tools`; no new `Node2D` roots, no flag clusters,
  `device == -1` filtering intact, no network/telemetry/PII added, `# story:` tags present, saves untouched.
