# e14s02: Hubs on the player: title, home, village, celebration

## 1. Story Goal

A child can start, move through the house, visit the village and collect the cycle reward, all as data
on the player. Doors open scene ids. The legacy hubs stay bootable until e14s05.

## 2. Requirements

#### ADDED: Title, home, village and celebration as scene data
**After:** `title.tres` is `t0_title` with one target that opens `home`. `home.tres` is `t25_map`: doors for `kitchen`, `bathroom`, `closet`, `playroom`, `bedroom` and `village`, locks read from `CareLoopManager`, and a locked door dims, plays a soft sound and points at the next care step. `village.tres` is `t25_map` plus one `t20_drag_snap` step for the recycling bag. `celebration.tres` is `t32_reward`.

#### ADDED: Village destinations grow only when the target def exists
**After:** At the end of this story, `village.tres` opens `home` and runs recycling. `market`, `playhouse`, `party`, `album` and `wheel` are added to that def by the story that writes their `.tres` (e14s03, e14s04). A destination string that is not a `SceneCatalog` id is rejected and logged. No def value is concatenated into a `res://` path.

## 3. Acceptance Criteria

1. **Strict typing and lint:** fully annotated; lint and format pass; 300-line and 20-line bars hold on every new or changed file. New scripts and tests start with `# story: e14s02`. Tests use `TestReset`.
2. **Title has one verb:** one interactive target, intro music `main_theme`, no second button, no text. The target requests scene id `home`.
3. **Home is a map of ids:** the six destinations above resolve through `SceneCatalog`. A value absent from the catalog is rejected and logged (`scene.def_rejected` or `map.destination_rejected`). Locks never show a price and never read the wallet.
4. **Recycling pays once per session:** the bag is a `t20_drag_snap` step on the village def. The second drop in the same session does not pay again (the legacy once-per-session guard). Payment stays in `ProgressManager`, not in the template.
5. **Celebration pays once per cycle:** coins and the star go through the existing `CareLoopManager` cycle guard. Re-entry shows the star already lit and pays nothing. The gift is free. There is no ad branch. Voice key `vo.celebration.congrats`.
6. **Voice and music stay the legacy keys:** title and home use `vo.home.welcome` on home only (title has no voice key today); village uses `vo.village.welcome`. Music ids resolve to the streams those scenes already play.
7. **No network, old scenes remain:** no `HTTPRequest`, `HTTPClient` or `WebSocketPeer`. `find game/scenes -name '*.tscn'` still returns 18 files. Both aspects, 0 px letterbox, on home and village.

## 4. Zoom-Out on the Modules This Touches

**`SceneCatalog`** — purpose: be the only resolver from a scene id to a def or, until e14s05, a legacy path.

- Callers: `SceneManager`, `PoiTable`, `FriendCatalog`, `t25_map`, tests.
- Contracts to preserve: unknown ids are rejected; a def string is never joined onto `res://scenes`. While legacy scenes exist, `PoiTable` may still answer with a path for the old `vila.tscn` (e13s03). The new village def does not.

**`CareLoopManager`** — purpose: own door dimming and the once-per-cycle reward.

- Callers: home locks, celebration, care rooms.
- Contracts to preserve: the reward amount and the once-only rule stay in the service. `t32_reward` displays and triggers.

## 5. Frozen Contracts

### Destinations are catalog ids

Same rule as `SC-e13s03-P0-05`. This story does not add a second resolver.

### A locked door is never a scolding

Refusal is a sound and the wish bubble for the next care step. No text, no shake, no price.

### The legacy hubs keep booting

`titulo.tscn`, `casa.tscn`, `vila.tscn` and `celebracao.tscn` stay until e14s05. `next_scene_id: home` on the kitchen def keeps the meaning it has today.

## 9. Risks

- **A map destination built by string join** leaves `res://scenes` (F-3). Mitigation: `SC-e14s02-P0-02` passes a path-shaped string and asserts rejection plus a log event.
- **Celebration pays twice** by re-entry or the mouse echo. Mitigation: `SC-e14s02-P0-04` enters twice under `TouchSim`.
- **Recycling pays on every visit.** Mitigation: the session guard is asserted, not reimplemented in the def.
