## 1. Story Goal

The care day after the kitchen, played on the one player. Bathroom, closet, playroom and bedroom are
scene data. Each credits its care step once. The seventeen legacy scenes stay on disk until e14s05 (D1).

## 2. Requirements

#### ADDED: Four care rooms as scene data
**After:** `res://data/scenes/bathroom.tres`, `closet.tres`, `playroom.tres` and `bedroom.tres` run on `scene_player.tscn`. Bathroom is three steps: soap on `t40_draw_fill`, rinse on `t23_erase`, dry on `t23_erase`. Closet is `t45_dress_decorate`. Playroom and bedroom are `t21_touch_each`. The player calls `CareLoopManager.complete_step` once per visit for `BATH`, `DRESS`, `PLAY` and `SLEEP`.

#### ADDED: The rooms are reachable by id without deleting the old scenes
**After:** `SceneCatalog` resolves `bathroom`, `closet`, `playroom` and `bedroom` to those defs. `banheiro.tscn`, `closet.tscn`, `jardim.tscn` and `quarto_sono.tscn` still exist, and their scripts still boot.

## 3. Acceptance Criteria

1. **Strict typing and lint:** every new or changed file is fully annotated; `gdlint` and `gdformat --check` pass; no new or changed file exceeds 300 lines; no new or changed function exceeds 20 non-comment lines. Each new script and test starts with `# story: e14s01`. Tests call `TestReset` and write `user://test_progress.json` only.
2. **Bathroom is the three-step def e13 already specified:** soap, then rinse, then dry. The completing step sets `care_step_id` to `BATH` and `next_scene_id` to `home`. One visit credits `BATH` once. If e13 already wrote `res://data/scenes/bathroom.tres`, this story adopts that file. It does not add a second bathroom def.
3. **Closet dresses from data:** four outfits (`floral_dress`, `red_dress`, `green_overalls`, `pajamas`) and six accessories (`flower_tiara`, `crown`, `yellow_hat`, `blue_scarf`, `purple_bow`, `heart_glasses`) snap through `t45_dress_decorate`. The look saves with `ProgressManager.equip`. The room opens already dressed from the save. `DRESS` is credited once per visit. An id that fails `Ids.is_valid` is rejected before any save call.
4. **Playroom counts three distinct toys:** `ball`, `pinwheel` and `plush` are the `count_n` set on `t21_touch_each`. A second touch on a spent toy replays its reaction and does not advance the count. `PLAY` is credited once. The tickle zone is included only as a reaction the shipped template already replays without changing progress. This story adds no tickle mode.
5. **Bedroom finishes in either order:** lamp and plush are two `t21_touch_each` targets. Either may be first. `SLEEP` is credited once when both are done. The night tint is applied to the background only, never to `QuiQuiRig`. There is no bedtime voice key (the legacy room has none).
6. **No network and no new template:** the story adds no `HTTPRequest`, `HTTPClient` or `WebSocketPeer`, and it does not change `t40`, `t23`, `t45` or `t21`. Room nouns stay in the defs.
7. **Both aspects, old scenes still present:** the bathroom hull is checked at `1920×1080` and `2048×1536`. `find game/scenes -name '*.tscn'` still returns 18 files.

`t40`, `t23`, `t45` and `t21` read the `StepDef` only. Foam, towel, outfit ids and toy ids are def values.

## 9. Risks

- **A second `complete_step` on re-entry** double-counts the care day. Mitigation: each end-to-end test enters the room twice and counts calls.
- **Closet saves an id the child does not own a slot for.** Mitigation: `Ids.is_valid` runs before `equip`, asserted by `SC-e14s01-P0-02`.
- **Night tint on the rig** hides the face, which is the only feedback a pre-reader has. Mitigation: `SC-e14s01-P0-04` asserts the rig modulate is unchanged.
