# e05s01: Layered Outfit & Accessories + the Persisted Look

<!-- story: e05s01 -->
- **Epic:** `e05-closet-dress-scene`
- **BCP:** 4
- **Playable Vertical Target:** `res://scenes/closet.tscn`
- **Delta:** `ADDED`
- **Threat findings closed here:** T-E05-01 (ids from the save), T-E05-03 (layer order), T-E05-04
  (corrupt save), T-E05-05 (one accessory per slot), T-E05-06 (mouth zone stays clear)

## 1. Story Goal
What she wears is a **choice**, not a sprite toggle: three accessory slots on top of the outfit slot, one
item per slot, ids validated before they reach a `res://` path, and the whole look persisted so the next
room she walks into already shows it. The face stays above the outfit and every accessory is placed so it
cannot reach the mouth zone.

## 2. Acceptance Criteria
1. **Strict Typing & Lint:** `gdlint game/ && gdformat --check game/` exits `0`, type gate passes.
2. **Explicit State Machine:** no new machine is needed here; the closet's DRESS machine arrives in e05s02.
   This story adds no boolean flag clusters.
3. **Touch & Mouse-Echo Safety:** unchanged in this story; the closet's `SNAP_TO_SLOT` gesture is e05s02.
4. **Dual-Aspect Responsive Layout:** accessory placement is a function of the **mouth zone**, so it holds
   at `1920x1080`, `1920x1440` and `2048x1536` without a per-canvas constant.
5. **Observability & Traceability:** `logs.sh audit --self-test` and `trace-stories.sh --strict` exit `0`.
6. **Slots:** `body`, `head`, `neck`, `eyes`. One item per slot: a second hat replaces the first (T-E05-05).
7. **Validated ids (T-E05-01):** `../etc/passwd`, `TIARA`, `a`×65 and `id.with.dot` are refused by both the
   rig and the manager, and nothing changes.
8. **Layer order (T-E05-03):** the expression stays above the outfit and visible; no accessory art
   contains the mouth-zone centre (T-E05-06).
9. **Persistence:** `equip(slot, id)` writes and saves; `equipped(slot)` reads; a reset + reload brings
   the look back. `dress(rig)` applies the saved look to a rig without a closet.
10. **Corrupt save (T-E05-04):** an invalid slot or id in the file is dropped on load, and the room still
    plays with the default look.

## 4. Test Scenarios
- `SC-E05-P0-01` the expression stays above the dress, and no accessory art contains the mouth centre
- `SC-E05-P0-02` a second accessory in a slot replaces the first, other slots untouched
- `SC-E05-P1-03` invalid ids are refused by the rig and change nothing
- `SC-E05-P1-04` an unknown slot is refused and the rig keeps rendering
- `SC-E05-P0-05` equip → save → reset → load brings the look back from disk
- `SC-E05-P1-06` equip refuses invalid slots and ids
- `SC-E05-P1-07` `reset()` clears the accessories with the outfit
