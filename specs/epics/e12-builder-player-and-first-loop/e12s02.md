## 1. Story Goal

Introduce the description a scene is made of (background, music, voice keys, steps, reward, next) and
the navigation that carries it: the engine opens one player scene and hands it the description instead of
opening one `.tscn` per room. Legacy rooms keep working through the same table while they still exist
(D1a), so the tree has one navigation entry point from day one.

## 2. Requirements

#### ADDED: A scene is described by data
**After:** `SceneDef` (background, music, voice keys, steps, reward, next) and `StepDef` (template id + typed parameters + reactions) are typed `Resource` classes. A def that names an unknown template, fails `Ids.PATTERN`, has no background or has no steps is rejected at load with `scene.def_rejected` and a reason.

#### ADDED: Navigation by scene id
**After:** `SceneManager.request_def(id)` drives the same FSM, curtain, watchdog and pending slot as `request_scene(path)`; the swap target is always `res://scenes/scene_player.tscn`, and the chosen def travels through `pending_def`/`consume_def()` because `change_scene_to_file` is deferred and takes no arguments.

## 3. Acceptance Criteria

1. **Strict Typing & Lint:** every new script fully annotated; `gdlint`/`gdformat` pass; 300/20 bars hold.
2. **Typed data:** `SceneDef` and `StepDef` are `Resource` classes with typed exports, so the inspector and the loader agree; a step names a template id and its typed parameters.
3. **Validated on load:** an unknown template id, an id that fails `Ids.PATTERN`, a missing background or an empty step list is rejected with `scene.def_rejected` and a reason — never a half-built scene.
4. **One entry point:** `SceneManager` gains `request_def(id)` beside the legacy `request_scene(path)`; both drive the same FSM (`IDLE→FADING_OUT→SWAPPING→FADING_IN`), curtain, 2.0 s watchdog and 1-slot pending queue.
5. **No argument-passing trick:** the chosen def travels through the autoload (`pending_def` / `consume_def()`), because `change_scene_to_file` is deferred and takes no parameters; a second read returns empty so a reload cannot reuse a stale def.
6. **Table, not files:** `SceneCatalog` maps scene id → either a legacy path or a def path, so `PoiTable`, `FriendCatalog` and the MBT/gallery tests read ids from one place.
7. **No path, no script, no code (F-2):** neither `SceneDef` nor `StepDef` carries a path-shaped field (no `script`, no `resource_path`), and the template registry is a closed `const` map from template id to script — a def can name an id, never a destination (`SC-e12s02-P0-08`).
8. **Observability & Traceability:** the diary id is unchanged (`scene.kitchen`); `logs.sh audit --self-test` and `trace-stories.sh --strict` exit `0`.

## 4. Zoom-Out on the Modules This Touches

**`SceneManager`** — purpose: own scene transitions as an explicit machine with a fade curtain, a 2.0 s watchdog and a 1-slot pending queue.

- Callers: 17 scene scripts (`titulo`, `casa`, `roda`, `album`, `festa`, …) call `request_scene(path)`; `care_loop_manager` reacts to detours; `test_scene_manager` asserts the FSM; MBT/gallery/monkey iterate `SceneCatalog.ALL_PATHS`.
- Contracts to preserve: `request_scene` keeps working unchanged until e14s05. `_slug()` must keep producing `scene.kitchen`. The watchdog and the rejection codes (`empty_path`, `same_scene`) must not change meaning. `production_swap` stays the test seam.

**`SceneCatalog`** — purpose: be the one list of playable scenes the tests walk.

- Callers: `test_visual_gallery`, `test_mbt_random_walk`, `test_monkey_fuzz`, `gallery_capture`.
- Contracts to preserve: `ALL_PATHS`/`SCENE_COUNT`/`is_shipped` may not disappear while legacy scenes exist; ids are added beside them and `is_shipped` accepts both shapes.

## 5. Frozen Contracts

### The state machine is reused, not rewritten

`SceneManager`'s FSM, curtain, watchdog, pending slot and rejection codes stay verbatim. Only the target resolver and the payload channel are new.

### Ids are grammar-checked before they become paths

`res://data/scenes/<id>.tres` is built only after `Ids.is_valid(id)` (CONVENTIONS §4 input validation).

### A def cannot run code

Scene data never contains code: no script paths, no expressions. `StepDef` holds ids and numbers.

## 8. Out of Scope

- Migrating any of the 17 rooms (e14).
- The step machine itself (e12s03).

## 9. Risks

- **Two navigation mechanisms coexist by design (D1a).** The failure mode is a room that opens by one path and cannot be reached by the other. Mitigation: one id table, and `is_shipped` accepts both shapes so the gallery/MBT keep covering legacy rooms.
- **A def path built from an unvalidated id is a path-traversal shape.** Mitigation: `Ids.is_valid` before every `res://data/scenes/<id>.tres` — the same rule BUG-008/BUG-012 established, with the `security: low` tasks asserting no new findings.
- **The deferred swap silently reusing a stale def** would show the wrong room. Mitigation: `consume_def()` clears on read, pinned by a test that reads twice.
- **`_slug()` drift would break the diary vocabulary** the auditor and the PII policy depend on. Mitigation: a test asserting `scene.kitchen` is still the emitted id.
