# e04s01: TouchDraggable CONTINUOUS_SCRUB Mode & QuiQuiRig Local-Space ScrubHull Polygon

<!-- story: e04s01 -->
- **Epic:** `e04-bathroom-bath-scene`
- **BCP:** 3
- **Playable Vertical Target:** `res://scenes/banheiro.tscn`
- **Delta:** `ADDED`
- **Threat findings closed here:** T-E04-01 (hull drift on resize, HIGH), T-E04-04 (gesture
  wedge, HIGH), T-E04-03 (diary flood), T-E04-05 (SFX channel held past the gesture)

## 1. Story Goal
A sponge can be rubbed across QuiQui and the game knows *where* the rubbing happened: presses and moves
become `scrubbed` events carrying a global point, but only while the finger is inside a hull polygon
authored in rig-local space. The hull is derived from the rig's **opaque** rect on every layout pass, so
it lands on her body at 16:9 and 4:3 alike — the failure mode T-E04-01 names is invisible at 16:9, which
is why the oracle asserts both. An interrupted scrub must never leave the shared finger owner latched
(T-E04-04).

## 2. Acceptance Criteria
1. **Strict Typing & Lint:** `gdlint game/ && gdformat --check game/` exits `0`, and the type gate passes.
2. **Explicit State Machine:** the scrub gesture is a `Fsm` (`res://scripts/core/fsm.gd`) with legal
   edges only, and zero `fsm.illegal_transition` / `fsm.dwell_timeout` under `FsmProbe`.
3. **Touch & Mouse-Echo Safety:** `device == -1` synthesized mouse events are ignored; one press produces
   one gesture under `TouchSim` with the echo present.
4. **Dual-Aspect Responsive Layout:** `GeometryOracle` passes at `1920x1080` and `2048x1536`, and the hull
   containment check passes at `1920x1080`, `1920x1440` and `2048x1536`.
5. **Observability & Traceability:** `bash scripts/logs.sh audit --self-test` and
   `bash scripts/trace-stories.sh --strict` exit `0`.
6. **Scrub semantics:** with `mode == CONTINUOUS_SCRUB`, a press moves `REST -> SCRUBBING`; every move
   inside the hull emits `scrubbed(global_point)` exactly once per event; release moves
   `SCRUBBING -> REST`. `consumed` is never emitted in this mode; there is no drop target.
7. **Hull is derived, never authored twice:** `QuiQuiRig.scrub_hull_global() -> PackedVector2Array`
   returns the hull in global coordinates, built from `get_visual_global_rect()` shrunk by
   `SCRUB_HULL_INSET`, and recomputed whenever the rig resizes (`NOTIFICATION_RESIZED`) or its art
   changes. A hull cached at one canvas size is a bug: `test_the_hull_follows_the_opaque_rect_on_every_canvas`.
8. **Outside the hull means no scrub:** a move whose point is outside the polygon emits nothing and does
   not change state; the gesture stays `SCRUBBING`, so re-entering the hull resumes scrubbing.
9. **Owner latch survives interruption (T-E04-04):** the static single-finger owner is released on
   release, on `_exit_tree`, and on an explicit `abort()` used by scene changes. Starting a scrub and
   freeing the node mid-gesture must leave the next `TouchDraggable` fully draggable.
10. **One channel, one gesture (T-E04-05):** the optional scrub loop is a single owned player started on
    `REST -> SCRUBBING` and stopped on `SCRUBBING -> REST` / `abort()` / `_exit_tree`; it never outlives
    the gesture and never owns more than one of the 8 SFX channels.
11. **No diary flood (T-E04-03):** two scene events per gesture — `scrub.start` and `scrub.end` —
    carrying the hull size and the scrubbed count, never the motion points. The diary grows with the
    *gesture count*, not with the motion count: a 40-motion scrub writes exactly what a 2-motion scrub
    writes (plus the two `fsm.transition` lines the Fsm writes by design).
12. **Coordinates:** identical conversion contract to `CONSUME_ON_DROP`; every test feeds events through
    `TouchSim.gui_event`, so the local-vs-global conversion is exercised, not assumed.

## 3. Frozen Contract
`game/scripts/components/touch_draggable.gd` gains one mode and one signal; nothing existing changes.

```gdscript
signal scrubbed(global_point: Vector2)   # CONTINUOUS_SCRUB only, inside the hull
var scrub_target: Control = null         # duck-typed: must expose scrub_hull_global()
const SCRUB_HULL_INSET: float = 12.0     # canvas px, shrinks the opaque rect into the body
```

`game/scripts/components/quiqui_rig.gd` gains the hull, in rig-local authoring space:

```gdscript
const SCRUB_HULL_POINTS: int = 12        # polygon resolution around the body
func scrub_hull_global() -> PackedVector2Array   # global coords, rebuilt on layout pass
func scrub_hull_local() -> PackedVector2Array    # rig-local, for tests and art alignment
```

`touch_draggable` FSM gains `SCRUBBING` with edges `REST -> SCRUBBING -> REST` and
`SCRUBBING -> ABORTED -> REST`; the enum value `CONTINUOUS_SCRUB` that e03 reserved is now live.
`CONSUME_ON_DROP`, `SNAP_TO_SLOT` and `FREE_PLACEMENT` behaviour are untouched.

## 4. Test Scenarios
- `SC-E04-P0-01` a drag inside the hull emits `scrubbed` per move and never `consumed`
- `SC-E04-P0-02` a move outside the hull emits nothing and leaves the gesture `SCRUBBING`
- `SC-E04-P0-03` the hull follows the opaque rect at `1920x1080`, `1920x1440`, `2048x1536` (T-E04-01)
- `SC-E04-P0-04` scrubbing then freeing the node mid-gesture leaves the next drag working (T-E04-04)
- `SC-E04-P0-05` a 40-motion gesture writes exactly as much as a 2-motion gesture (T-E04-03)
- `SC-E04-P1-06` the scrub loop occupies one channel and stops on release and on `abort()` (T-E04-05)
- `SC-E04-P1-07` mouse echo produces one gesture, not two
- `SC-E04-P2-08` `scrub_target == null` degrades to "no hull, no scrubs" without an error
