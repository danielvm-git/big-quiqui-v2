## 1. Story Goal
A food can be picked up with one finger, follows that finger, and is either consumed on a drop target or flies back to its place. Criterion 4 applies to the component's own hit box here; the dual-aspect scene check is e03s03.

## 2. Acceptance Criteria
1. **Strict Typing & Lint:** `gdlint game/ && gdformat --check game/` exits `0`, and the type gate passes.
2. **Explicit State Machine:** Any stateful behavior uses `Fsm` (`res://scripts/core/fsm.gd`) with zero `fsm.illegal_transition` or `fsm.dwell_timeout` events under `FsmProbe`.
3. **Touch & Mouse-Echo Safety:** Interactive controls filter `device == -1` synthesized mouse echo and act once when the echo is present.
4. **Dual-Aspect Responsive Layout:** `GeometryOracle` passes at both `1920x1080` (16:9) and `2048x1536` (4:3 iPad) with zero letterbox bars and `>=120x120 px` hit targets.
5. **Observability & Traceability:** `bash scripts/logs.sh audit --self-test` and `bash scripts/trace-stories.sh --strict` exit `0`.
6. **Pick up and follow:** a press on the control moves `REST -> DRAGGING`; each move keeps the grab offset, so the art does not jump under the finger.
7. **Drop on target:** releasing with the finger inside `drop_target`'s global rect grown by `drop_margin` moves `DRAGGING -> CONSUMED` and emits `consumed` exactly once. `CONSUMED` is terminal: later events do nothing.
8. **Drop elsewhere:** `DRAGGING -> RETURNING`, moving back to the rest position in `RETURN_SEC`, then `REST`. A press during `RETURNING` moves to `DRAGGING`.
9. **Single-finger lock:** only one `TouchDraggable` in the game can be held at a time (a `static` owner, released on `_exit_tree`), and only the owning touch index can move or drop it. A second finger is ignored.
10. **Mouse echo:** events with `device == -1` are ignored. A real mouse (`device == 0`) drags. A desktop mouse can also produce an emulated touch for the same gesture, so the FSM must make the duplicate harmless: one press, one drop, one `consumed`.
11. **Coordinates:** Godot's GUI dispatch gives `_gui_input` positions local to the control, using `get_global_transform_with_canvas()`. The component converts local to global with that transform, read per event because the control itself moves. `TouchSim` gains `gui_event(control, event) -> InputEvent`, which returns a copy with the local position GUI dispatch would give it, and every drag test feeds events through it.
12. **Disabled:** with `enabled == false` a press does nothing and the state stays `REST`.
13. **Hit box:** `_ready` enforces `MIN_HIT_SIZE`, `mouse_filter = STOP`.

## 3. Frozen Contract
`game/scripts/components/touch_draggable.gd` — `class_name TouchDraggable`, `extends Control`.

```gdscript
enum Mode { CONSUME_ON_DROP, CONTINUOUS_SCRUB, SNAP_TO_SLOT, FREE_PLACEMENT }
signal drag_started
signal drag_moved(global_point: Vector2)
signal drag_ended
signal consumed
const MIN_HIT_SIZE: Vector2 = Vector2(120.0, 120.0)
const RETURN_SEC: float = 0.25
var mode: Mode = Mode.CONSUME_ON_DROP
var drop_target: Control = null   # null means nothing can consume it
var drop_margin: float = 0.0      # grows the target rect, in canvas px
var enabled: bool = true
var manual_step: bool = false     # test seam: only advance() moves the machine
var fsm: Fsm = null               # fsm_id touch_draggable, states per EXPLICIT_STATE_MACHINES §3
func advance(delta: float) -> void
func state_id() -> String
```

Only `CONSUME_ON_DROP` behaviour is built. The other enum values exist for later epics and behave like `CONSUME_ON_DROP` without a target: a drop returns home.

## 4. Test Scenarios
