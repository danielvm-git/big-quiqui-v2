## 1. Story Goal

`t22_play_beat` (392 scenes, the most used template in the catalogue) and `t3_skip_beat` (130) are the
only two wave-1 templates whose behaviour is a guess: neither carries a distinctive component, so their
labels come from method names alone. This story buys the evidence before anyone builds them.

## 2. Requirements

#### MODIFIED: What we know about the two guessed templates
**Before:** The template table says `t22_play_beat` is a tableau where objects answer a touch and ends when the sounds finish, and `t3_skip_beat` is a short beat the child can skip. Both labels come from method names alone; neither scene carries a distinctive component.
**After:** Each template gets a written rule — what starts it, what ends it, what a scene supplies — with a confidence level and the evidence behind every claim, plus a build-or-skip call and the coverage number that follows from it.

## 3. Acceptance Criteria

1. **Written rule per template:** what it does, what starts and ends it, what a scene supplies, and a confidence level (`high` / `medium` / `low`) with the evidence behind each claim.
2. **Evidence is named:** the template class methods actually read, the sibling initializers inspected, and the objects those scenes carry (component names and counts), quoted as they appear.
3. **A build-or-skip call per template:** build, build with a stated assumption, or skip — with the consequence for the wave-1 coverage claim written out in the same document.
4. **Numbers restated honestly:** if either template is skipped, the 88.4% claim is rewritten with the number that remains, and the scope is updated rather than the text softened.
5. **No code:** this story ships a document at `specs/product/TEMPLATE_EVIDENCE_T22_T3.md` and changes no game file.

## 5. Frozen Contracts

### Untrusted input

The extracted Unity data is treated as hostile: scripts run with `-I`, live outside the data directory, and never write into `game/`.

### Names, not decompiled bodies

The evidence is component and method names plus scene object graphs. A claim that would need a method body is marked as inferred, not stated as fact.

### The document outlives the pass

The rule in the document is the one the template implements; if the implementation disagrees, the document is wrong and gets fixed first.

## 6. Implementation Steps

1. Re-extract the two templates' scene objects and template class methods, and record what they actually carry → `verify:` `test -s specs/product/TEMPLATE_EVIDENCE_T22_T3.md`
2. Write the rule, the confidence level and the build-or-skip call per template → `verify:` `bash scripts/validate-specs-yaml.sh`
3. Reconcile the coverage claim in `SCOPE_LATEST.yaml` with the decision and keep the gates green → `verify:` `bash scripts/preflight.sh --fast`

## 9. Risks

- **Confirming a guess with a guess.** Mitigation: every claim names its source (a method name, a field, an object count); anything that would need a decompiled body is labelled inferred.
- **The document drifting from the implementation.** Mitigation: e13s07's acceptance makes the document the specification, so a divergence is fixed in the document first.

## Verification Script

3. Is the confidence level honest (no claim about what a method body does)?
