## Story Goal
Deliver the outdoor hub `res://scenes/vila.tscn` — a panoramic, zero-letterbox world with six
interactive building POIs — and upgrade the shared `WishBubble` from a binary `HIDDEN`/`SHOWN`
prompt to an **escalating** one (calm → urge → insist) so a child who ignores QuiQui's wish sees
the want build instead of a static bubble. The Vila hub carries the same wish bubble as the Casa,
so the care loop is never lost when the child wanders outside.

**Why escalation, not a hunger simulation:** TutoTOONS' `HungerTimer` fires `ReachedQuarter` /
`ReachedHalf` milestones (engine report §3.2). Our loop has no hunger stat — the "want" is the next
care step. The faithful adaptation is: the longer the child idles without opening the next care
door, the more insistent the wish bubble becomes. No new loop semantics, no timers that block play.

## Acceptance Criteria
1. **Strict Typing & Lint:** `gdlint game/ && gdformat --check game/` exits `0`.
2. **Explicit State Machine:** any stateful behaviour uses `Fsm`; zero `illegal_transition` /

4. **Dual-Aspect Responsive Layout:** `GeometryOracle` passes at `1920x1080` (16:9) and `2048x1536`

5. **Observability & Traceability:** `logs.sh audit --self-test` and `trace-stories.sh --strict` exit `0`.

### FIX-01 — wish escalation (MODIFIED)
6. `WishBubble` gains a monotonic `urgency` level `0..2` (`calm`, `urge`, `insist`), clamped, with
   pulse amplitude and speed growing per level; `show_wish(icon_path)` keeps the old default
   (`urgency = 0`), so every existing caller and test is unchanged.
7. `hide_wish()` and `reset()` clear urgency to `0` — a hidden bubble is always at rest (same
   invariant as `pulse_scale() == 1.0` while hidden, BUG-005).
8. `casa.gd` escalates: the first prompt appears at `IDLE_WISH_SEC = 8.0` (urgency 0), then urgency
   rises one step every `ESCALATION_SEC = 6.0` to a ceiling of 2. Any touch (`_reset_idle`) resets
   to hidden and clears urgency.
9. `vila.tscn` mounts a `WishBubble` driven by the same constants and escalation; when the loop is
   mid-cycle the Vila shows which care step is next, never text.
10. Escalation is deterministic: with `manual_step` the timeline is a pure function of accumulated
    delta (same pattern as `WishBubble.advance`), so a test replay reproduces it exactly.

### VilaScene (ADDED)
11. Six building POIs, each a `TapButton` in the `hit_target` group, edge-anchored per ADR-008.
    Proposed set — **confirm before build**: `casa` (home), `roda` (wheel), `recycling`,
    `mercado`, `casinha`, `festa`. Doors to scenes that do not exist yet log `scene.pending`
    exactly like the e01 Play button; only `casa` and `roda` navigate.
12. The Vila closes a dangling `CELEBRATE` on arrival (`close_celebrate_if_needed`), mirroring
    `CasaScene` (T-E07-05) so the hub never arrives with six doors that all refuse.
