# e08s04: Economy conservation — non-negative balances & spin idempotency

## Story Goal
Lock **economy invariants** with GUT property tests: `coins` and `tickets` never go negative under any supported call sequence; **double-tap** (or rapid repeat) on the wheel spin control does not spend more than one ticket per logical spin. Complements e08s03’s scene tests by stressing the **manager** boundary and edge sequences.

**Why a dedicated story:** scene tests prove one path; property tests try to break the numeric contract across `add_*`, cycle rewards, wheel spend, and recycle earn.

## Acceptance Criteria
1. **Strict typing & lint:** full project lint + format pass as part of task verify.
2. **Tests:** New/extended tests in `game/tests/unit/` (and integration if needed) with `# story: e08s04`:
   - After any sequence of `add_coins`, `add_tickets`, `complete_cycle`, wheel spend API used by `WheelScene`, and `VilaScene` recycle reward paths, `get_coins()` ≥ 0 and `get_tickets()` ≥ 0.
   - Clamping: attempts to drive balances negative result in `0` (no crash, no negative read).
   - **Double-tap spin:** two programmatic `press()` or `tap_control` calls on the spin button **in the same IDLE window** do not reduce tickets by more than one (idempotency).
3. **No new network, ads, or telemetry.**
4. **Observability & trace:** `logs.sh audit --self-test` and `trace-stories.sh --strict` pass after changes.

## Frozen Contract
- **`SaveData` / `ProgressManager`:** public getters return clamped non-negative integers; mutators use `clampi` (existing `_apply`) — tests assert behavior, not implementation details.
- **`WheelScene`:** exposes a test seam `manual_step` and uses Fsm so a second `press()` while not `IDLE` is a no-op for economy (asserted in e08s04).

## Test Scenarios
- `SC-E08-P0-18` property: random interleave of add/subtract within sane bounds → balances never negative
- `SC-E08-P0-19` wheel double-tap → at most one ticket spent per spin start
- `SC-E08-P0-20` recycle + wheel + cycle reward interleave → non-negative
- `SC-E08-P2-21` trace + PII audit clean
