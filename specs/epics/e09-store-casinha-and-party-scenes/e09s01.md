# e09s01: FurnitureData Catalog (12 Lote-6 Pieces) & Playable Scene 11: StoreScene (mercado.tscn) Atomic Coin Purchase

- **Parity fix folded here:** `FIX-03` coin-travel juice + `FIX-05` prices in `EconomyData`

## Story Goal
The village gets its first **purchase** verb. A child walks into the furniture store, taps a piece,
and either owns it (coins travel from the HUD into the shelf) or hears/feels "not yet" — never a
crash, never a negative balance, never a double charge. The 12 Lote-6 furniture pieces become typed
data (`FurnitureData` + `.tres`), so the store, the casinha and the party all read one catalog and no
scene ever builds a `res://` path out of free text.

## Acceptance Criteria
1. **Strict Typing & Lint:** `gdlint game/ && gdformat --check game/` exits `0`.
2. **Explicit State Machine:** `StoreScene` is a table-driven `Fsm` (`IDLE -> PAYING -> SOLD -> IDLE`)
   with zero `fsm.illegal_transition` / `fsm.dwell_timeout` under `FsmProbe`.
3. **Touch & Mouse-Echo Safety:** every shelf `TapButton` fires once under
   `TouchSim.tap_control(..., with_mouse_echo=true)`; `device == -1` is filtered.
4. **Dual-Aspect Responsive Layout:** `GeometryOracle` passes at `1920x1080` (16:9) and `2048x1536`
   (4:3 iPad), zero letterbox, `>=120x120 px` hit targets.
5. **Observability & Traceability:** `logs.sh audit --self-test` and `trace-stories.sh --strict` exit `0`.

### FurnitureData & Catalog (ADDED)
6. `FurnitureData` (`Resource`) fields: `id: String`, `art_path: String`, `price_coins: int >= 0`.
7. `FurnitureCatalog.FURNITURE_IDS` lists exactly the 12 shipped Lote-6 pieces:
   `abajur, armario, beliche, cadeira, cama, escada, estante, mesa, porta, sofa, tapete, vaso_planta`.
   `all()` returns 12 items; `get_item(id)` returns `null` + `item.unknown` for anything outside the
   list (no path is ever interpolated from outside text), `item.missing_data` when the `.tres` is absent.
8. `EconomyData.furniture_prices` (FIX-05) is the one price table; `FurnitureCatalog.price_of(id, economy)`
   floors a negative price at `0`. A price of `0` still requires the purchase path (no free grant).

### Atomic purchase (MODIFIED)
9. `ProgressManager.buy_furniture(id, price) -> bool`:
   - `false` + **no** mutation when the id is invalid (`Ids`), the price is negative, coins are short,
     or she already owns it (`already_owned` event, idempotent — no second debit);
   - `true` + one debit + one `owned_furniture` append + **one** `save()` (atomic `.tmp` + rename) and
     **one** `progress_changed` otherwise.
10. `ProgressManager.owns_furniture(id) -> bool` and `owned_count() -> int` are the read side.
11. Purchases survive a reload: after `buy_furniture`, a fresh `load_or_default()` still owns the piece
    (the money path writes, exactly like `complete_cycle`).

### StoreScene (ADDED — `res://scenes/mercado.tscn`)
12. Background `bg_mercado`, `QuiQuiRig`, `CoinTicketHud`, `HomeButton`, four shelf `TapButton`s
    (`Shelf0..Shelf3`), a `SoldBadge` per shelf and a `NotEnough` shake target; all interactive nodes in
    `hit_target`, edge-anchored per ADR-008.
13. A tap on a shelf she owns is a no-op beyond the `sold` expression; a tap she cannot afford shakes the
    shelf and logs `store.denied` with `reason: coins`; a tap she can afford debits, flies the coin from
    the shelf to the HUD (FIX-03), shows the sold badge, and logs `store.buy` with `id` + `price`.
14. Coins/tickets are never written by the scene directly — `ProgressManager` owns money.
15. `HomeButton` returns to `casa.tscn`; the scene closes a dangling `CELEBRATE` on arrival.
16. The Vila's `MERCADO` door navigates to `mercado.tscn` (it stops being `scene.pending`).

## Frozen Contract

```gdscript
# game/scripts/resources/furniture_data.gd  (NEW)
class_name FurnitureData extends Resource
@export var id: String = ""
@export var art_path: String = ""
@export var price_coins: int = 0
func texture() -> Texture2D          # Ids-validated; null + diary line on bad/missing art

# game/scripts/core/furniture_catalog.gd   (NEW)
class_name FurnitureCatalog extends RefCounted
const FURNITURE_DIR: String = "res://resources/furniture/"
const FURNITURE_IDS: Array[String] = [ ...12 ids... ]
static func all() -> Array[FurnitureData]
static func get_item(id: String, dir: String = FURNITURE_DIR) -> FurnitureData
static func price_of(id: String, economy: EconomyData) -> int   # max(0, economy.furniture_prices[id])

# game/scripts/core/economy_data.gd        (MODIFIED — additive)
@export var furniture_prices: Dictionary = { "abajur": 3, ... }  # one entry per catalog id

# game/scripts/autoloads/progress_manager.gd (MODIFIED — additive)
func buy_furniture(id: String, price: int) -> bool
func owns_furniture(id: String) -> bool
func owned_count() -> int

# game/scripts/scenes/mercado.gd          (NEW — class_name StoreScene extends Control)
const STATE_IDLE: String = "IDLE"       # SOLD -> IDLE after SOLD_HOLD_SEC
const STATE_PAYING: String = "PAYING"
const STATE_SOLD: String = "SOLD"
@export var economy: EconomyData = null
var fsm: Fsm = null
func shelf_ids() -> Array[String]                  # the four ids on the shelves, for tests
func try_buy(id: String) -> bool                   # the one money path (tap handler delegates)
func advance(delta: float) -> void
```

## Test Scenarios
- `SC-E09-P0-01` the catalog lists 12 ids and every `.tres` loads with a real texture
- `SC-E09-P0-02` `get_item("../../etc")` returns null and logs `item.unknown` (no path interpolation)
- `SC-E09-P0-03` `buy_furniture` is atomic: coins, owned list and one save; reload still owns it
- `SC-E09-P0-04` purchase is idempotent and never overdraws (short coins, already owned, negative price)
- `SC-E09-P0-05` the store boots clean on both aspects, four shelves ≥120 px, oracle clean
- `SC-E09-P0-06` a tap buys once under `TouchSim` with the mouse echo; the sold badge appears
- `SC-E09-P0-07` an unaffordable tap mutates nothing and logs `store.denied`
- `SC-E09-P1-08` the Vila `MERCADO` door now navigates instead of logging `scene.pending`
- `SC-E09-P2-09` no text is required to play; PII audit clean

## Risks
- **Money path** (`ProgressManager`): every changed line is a save line. Mitigated by reusing the existing
  `_apply`/`save` atomicity and adding tests for overdraw and double-charge.
- **`vila.gd` is exactly at the 300-line bar** (grandfathered rules do not cover it): its three new POI
  paths replace three `""` values, adding zero lines.
