# e09s03: Playable Scene 13: HousePartyScene (festa.tscn) Unlocked at >=5 Placed Furniture Items with Friends Dancing

## Story Goal
A goal she can *see* before she can read: the party door in the Vila carries a lock badge that becomes
a star badge once five pieces of furniture are placed in the casinha. A **locked** party never scolds —
QuiQui points at the casinha and the door stays shut. An **unlocked** party is pure juice: three friends
bob and dance with her over confetti.

## Acceptance Criteria
1. **Strict Typing & Lint:** `gdlint game/ && gdformat --check game/` exits `0`.
2. **Explicit State Machine:** `HousePartyScene` is a table-driven `Fsm` (`LOCKED -> DANCING`,
   `DANCING -> LOCKED` on home), zero `illegal_transition` / `dwell_timeout` under `FsmProbe`.
3. **Touch & Mouse-Echo Safety:** the party's `HomeButton` and `CasinhaButton` fire once under
   `TouchSim.tap_control(..., with_mouse_echo=true)`.
4. **Dual-Aspect Responsive Layout:** `GeometryOracle` passes at `1920x1080` and `2048x1536`, zero
   letterbox, `>=120x120 px` hit targets.
5. **Observability & Traceability:** `logs.sh audit --self-test` and `trace-stories.sh --strict` exit `0`.

### Unlock rule (the one owner)
6. `PARTY_MIN_PLACED: int = 5` is the single threshold; `party_unlocked()` is
   `ProgressManager.placed_count() >= PARTY_MIN_PLACED`, so the Vila badge and the party scene can never
   disagree.
7. Under the threshold the party is `LOCKED`: no confetti, no dancing, friends hidden, the lock badge is
   visible, one `party.locked` diary line (`placed` + `needed`), and the only exits are home and the
   casinha door (pointing her at the verb that unlocks it).
8. At or above the threshold the party is `DANCING`: `pato`, `urso` and `pinguim` visible and bobbing with
   a deterministic phase (`advance`-driven, `manual_step` replayable), confetti emitting, one
   `party.dance` line with `placed`.
9. Unlock is evaluated on mount **and** on `progress_changed`, so placing the fifth piece and walking back
   in never needs a restart; a party that loses a piece re-locks (guarded transition, never a double
   dance line).

### Vila badge (ADDED component, no new lines in `vila.gd`)
10. `door_badge.gd` is a self-contained `Control` that shows `locked_art` while `party_unlocked()` is
    false and `unlocked_art` once true, refreshing on `progress_changed`; the Vila builder adds it as
    `PartyBadge` inside the `PoiFESTA` door, so the hub reads the same rule without owning it.
11. The Vila's `FESTA` door navigates to `festa.tscn`.

## Frozen Contract

```gdscript
# game/scripts/components/door_badge.gd (NEW)
class_name DoorBadge extends Control
@export var required_placed: int = 5
@export var locked_art: String = ""
@export var unlocked_art: String = ""
func unlocked() -> bool                     # ProgressManager.placed_count() >= required_placed
func refresh() -> void                      # swaps the texture, no-op on equal state

# game/scripts/scenes/festa.gd (NEW — class_name HousePartyScene extends Control)
const PARTY_MIN_PLACED: int = 5
const STATE_LOCKED: String = "LOCKED"
const STATE_DANCING: String = "DANCING"
const LEGAL_EDGES: Dictionary = { STATE_LOCKED: [STATE_DANCING], STATE_DANCING: [STATE_LOCKED] }
const BOB_PERIOD_SEC: float = 0.9
const BOB_HEIGHT_PX: float = 18.0
var fsm: Fsm = null
func party_unlocked() -> bool
func refresh_unlock() -> void               # mount + progress_changed entry point
func advance(delta: float) -> void          # bob phase; no-op while LOCKED
func friend_offsets() -> Dictionary         # {id: y_offset} for tests
```

## Test Scenarios
- `SC-E09-P0-01` the party boots `LOCKED` with four placed pieces, logs `party.locked` once
- `SC-E09-P0-02` five placed pieces boot it `DANCING`, friends visible, one `party.dance`
- `SC-E09-P0-03` dropping to four pieces via `progress_changed` re-locks without a second dance line
- `SC-E09-P0-04` the bob is deterministic under `manual_step` (same delta series, same offsets)
- `SC-E09-P0-05` both aspects are oracle-clean; home and casinha doors are ≥120 px and navigate
- `SC-E09-P1-06` `DoorBadge` swaps locked→unlocked on `progress_changed` and defaults to locked
- `SC-E09-P1-07` the Vila `FESTA` door navigates

## Risks
- **Double dance lines** on every `progress_changed`: mitigated by the guarded transition (the state is
  only entered once) and asserted by `SC-E09-P0-03`.
- **`vila.gd` line budget:** no logic is added there; the badge is a component and the door path replaces
  an existing `""`.
