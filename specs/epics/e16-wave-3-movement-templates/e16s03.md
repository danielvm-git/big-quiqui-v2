REQ-16 was confirmed. This story does not change an acceptance criterion. `t47_drag_release` is folded
into `t20_drag_snap` because REQ-16 already says so.

## 1. Story Goal

`t52_groom` combs and dries a strand layer, and only then offers a trim. `t47_drag_release` becomes a
written rule and a regression on the existing `t20` drag path. `t53_outro` is one tap that goes home.
The drag fold does not fork `TouchDraggable` and does not grow `touch_draggable.gd`.

## 2. Requirements

#### ADDED: t52_groom
**After:** A strand layer in the def is rubbed with the existing Rub primitive. Tool order is an `Fsm`: comb, then dry, then trim. Trim stays disabled until comb and dry have both reported progress. The 120 px control is the tool, not each strand. Art ids in the probe already exist in `game/assets/`; this story adds none.

#### ADDED: t47_drag_release as a rule on t20
**After:** Release on the target snaps. Release off the target returns the piece. Both outcomes go through `t20_drag_snap` and the existing Give→Receive modes of `TouchDraggable` (`CONSUME_ON_DROP`, `SNAP_TO_SLOT`). There is no `t47_drag_release.gd`, no new drag mode, and no edit that grows `touch_draggable.gd` (grandfathered at 326 lines, INV-09).

#### ADDED: t53_outro
**After:** One tappable target. The tap asks `SceneCatalog` for the scene id `home` and `SceneManager` performs the swap. The id is not concatenated into a `res://` path. The screen has no second target, no ad, and no policy link.

#### REMOVED: A second drag primitive and a scissor-first salon
**Before:** TutoTOONS ships `Template47Draggable` beside `Template20`, and `Template52` can `RemoveStrand` with scissors as a peer of the comb.
**After:** (removed) — one drag surface answers release-right and release-wrong; scissors wait until comb and dry have progress.

## 3. Acceptance Criteria

1. **Strict Typing & Lint:** fully annotated; lint/format pass; bars hold. `touch_draggable.gd` does not grow.
2. **Groom order is data:** comb → dry → trim, declared as an `Fsm` with `legal_edges` and `max_dwell_sec`. Trim does not run first.
3. **The tool is the hit target:** the comb/dryer meets 120×120 px. Strands are hull samples under that tool.
4. **`t47` does not fork `TouchDraggable`:** no second drag script, no new mode, no subclass. The fold test drives `t20`.
5. **Outro goes home by id:** the only interactive target resolves `home` through `SceneCatalog`. A value absent from the catalog is rejected and logged. It is never a filesystem path.
6. **No ads, no network, no photo capture** in groom or outro.
7. **Probe defs on `res://scenes/scene_player.tscn`.** No new art, voice, `.tscn`, care step, or save field.
8. **Echo filter** on every new input handler. New files carry `# story: e16s03`.

## 4. Zoom-Out on the Modules This Touches

**`TouchDraggable`** — purpose: the only drag surface. Four modes, one finger, echo filtering.

- Callers: the legacy rooms plus `t20` / Give→Receive.
- Contracts to preserve: 326 lines, grandfathered by INV-09, so it may not grow. Primitives wrap it. This story does not edit it. Reason for depth: the fold is a rule on `t20` because a `t47` script would be a second drag primitive.

**`t20_drag_snap`** — purpose: snap a piece to its target or return it on a miss.

- Callers: kitchen and every other drag def.
- Contracts to preserve: wrong drop returns the piece and does not decrement progress (e12s06). The fold pins that contract under the `t47` name. It does not add a mode.

**`SceneCatalog` + `SceneManager`** — purpose: resolve a scene id, then swap with the existing curtain and watchdog.

- Callers: `t25_map`, `t0_title`, the home control.
- Contracts to preserve: ids match `\A[a-z0-9_]{1,64}\z`. Unknown ids are rejected. `t53` adds no path builder.

**`Rub`** — purpose: covered-area progress and one loop channel.

- Callers: reveal, erase, draw.
- Contracts to preserve: `t52` supplies a strand list and a tool order. It does not add a Rub mode.

No new package. Godot 4.7 and GUT stay `[OK]`.

## 5. Frozen Contracts

### One drag surface

Release-correct and release-wrong are `t20` outcomes. `TouchDraggable` stays the component that moves the piece.

### Trim is last

The groom `Fsm` has no edge from the start state to trim. A def that lists scissors first still cannot fire them until comb and dry have progress.

### Home is an id

`t53` passes `home`. `SceneCatalog` is the only resolver.

## 9. Risks

- **A `t47` script "just for the events".** That is the fork this story exists to prevent. Mitigation: `SC-e16s03-P0-03`.
- **Growing the grandfathered drag file** while wiring release-wrong. Mitigation: the fold test fails if `touch_draggable.gd` differs from its e16-base content; INV-09 already fails a one-line growth.
- **Outro concatenating `res://scenes/` + a def string.** Mitigation: `SC-e16s03-P0-04` passes a path-like value and expects a catalog rejection.
- **Scissors available on the first frame.** Mitigation: `SC-e16s03-P0-01` fires the trim edge from the start state and expects refusal.
