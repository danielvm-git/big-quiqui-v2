## 1. Story Goal

`t49_progress_holder` shows the step's progress so a later title can use it as data. The completeness
gate then closes the library: 28 buildable slots are real, 14 numbers stay empty, and the two ad
templates stay retired. QuiQui Care gains no step.

## 2. Requirements

#### ADDED: t49_progress_holder
**After:** The holder displays the ratio the runner already reports for the active step. A tap on the step's own targets still uses Tap. The holder does not end the step, does not start a timer, and does not write `SaveData`. The probe def is the test scene, played by `res://scenes/scene_player.tscn`.

#### ADDED: The 28-slot completeness gate
**After:** A test reads the template table and the scripts on disk. It fails unless each id below has a written adaptation rule and a test scene (a player probe def, or for `t47_drag_release` the `t20` fold test from e16s03). ## 3. Acceptance Criteria

1. **Strict Typing & Lint:** fully annotated; lint/format pass; bars hold.
2. **`t49` displays runner progress only:** the ratio comes from the step runner. No timeout, no step completion inside the holder, no save write.
3. **28 rules and 28 test scenes:** the table and the gate agree with the id list in §2. `t47_drag_release` counts as the e16s03 fold (a rule plus the `t20` test), not as a new template class.
4. **14 numbers stay reserved:** the gate fails if a script or registry row appears for any listed number.
5. **Both ad templates stay unbuilt:** the gate fails if T39 or T54 appears as a template id, an ad verb, or a script.
6. **No care step and no save redesign:** the probe is not registered on `CareLoopManager`. `SaveData.version` is unchanged.
7. **The wave-1 gate stays:** e13s09's thirteen-template check is still true. This gate adds the library total. It does not lower the wave-1 claim.
8. **Trace:** `# story: e16s04` on every new script and test.

## 4. Zoom-Out on the Modules This Touches

**`StepRunner`** — purpose: run one template step and expose its progress ratio.

- Callers: `ScenePlayer`, every template.
- Contracts to preserve: the runner decides completion. `t49` reads the ratio. It does not call complete, and it does not add a dwell that can trap input.

**Template registry (closed const map, e12)** — purpose: load a template by id only.

- Callers: the player, the wave-1 completeness test.
- Contracts to preserve: the map stays a closed `const`. Reserved numbers and T39/T54 are absent. A def name never becomes a filesystem path.

No new package. Godot 4.7 and GUT stay `[OK]`.

## 5. Frozen Contracts

### The holder is a view

Progress already exists on the runner. `t49` shows it. A second progress counter inside the template would drift from the step.

### Empty numbers stay empty

Initializer classes in the TutoTOONS dump are not evidence. The 14 numbers have no QuiQui script.

### Ads stay retired

The gift T39 gated is already free inside `t32_reward` (e13). T54 has no equivalent. This gate keeps both out of the registry.

## 9. Risks

- **The gate reading only the table it was copied from.** Mitigation: `SC-e16s04-P1-02` also requires a script or, for `t47`, the fold test file, on disk.
- **Counting `t47` twice or not at all.** Mitigation: `SC-e16s04-P1-04` asserts one slot, satisfied by `t20`, and fails if `t47_drag_release.gd` appears.
- **A progress holder that completes the step at 100% by itself** and fights the runner. Mitigation: `SC-e16s04-P1-01` sets the ratio to 1 and asserts the step machine did not move.
- **The gate depending on e15 templates that are not in this capsule.** That is the sequence: e15 lands `t27`, `t38`, `t43`, `t44`, `t55` first. Until they exist the gate stays `failing`, which is the ledger this plan starts from.
