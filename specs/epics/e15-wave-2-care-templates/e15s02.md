## 1. Story Goal

The Sequence modifier, shipped through `t55_find`, so ordered tapping arrives with a Care scene that
uses it. Tap itself stays the three modes from e13s02. e13s02 deferred Pairs and Sequence together;
this cut binds Sequence to `t55` and leaves Pairs with `t27` in e15s03, which is what the design
caption already says.

## 2. Requirements

#### ADDED: Sequence modifier
**After:** An ordered list of target ids from the step def. Only the active id advances the sequence. Reason for Depth: the order is the behaviour, and a cluster of booleans is banned; Tap's three modes stay closed, so Sequence sits on top of Tap instead of becoming a fourth mode.

#### ADDED: t55_find
**After:** The indicator shows the active target. A tap on it plays that target's reaction and advances. A tap on any other target still answers in the same frame and does not advance. The prompt is a voice key in the def, plus the indicator, so the child never has to read.

#### ADDED: Adaptation rule for t55_find
**After:** The design rule stands: a timer may show elapsed time, and it never ends the step. `AddAutoEndTimer`, `InitTimerBar` and `TimeOut` have no counterpart. `Fsm.max_dwell_sec` on the waiting state does not advance the sequence and does not complete the step. The voice line is a key that already resolves. This story adds no `.ogg`. FindNextActive is the active id in the def, not code that knows the room.

#### REMOVED: A clock that ends the find
**Before:** Every TutoTOONS `t55` scene carries `Template55Clickable`, `Indicator` and `Timer`, and the template can end on `TimeOut`.
**After:** (removed) — the indicator stays; the ending clock does not. The step ends when the child has tapped the targets in order.

#### ADDED: The find scene
**After:** `res://data/scenes/find_toy.tres` is a Care play scene on the player. Its one step names `t55_find` and lists existing toy ids in order. The id `find_toy` is in `SceneCatalog` and is an unlocked map destination. It is not a CareLoopManager step.

## 3. Acceptance Criteria

1. **Strict Typing & Lint:** fully annotated; lint/format pass; bars hold.
2. **Sequence is a modifier on Tap:** states are the def's ordered ids plus done, with `legal_edges` only to the next id. Tap stays `any` / `count_n` / `toggle`. The modifier is not inside `tap_button.gd`.
3. **Only the active target advances:** a correct tap advances once; a repeat on a spent target replays its reaction and does not move the index; a wrong target answers and stays put.
4. **The timer never ends the step:** showing elapsed time is a def flag and defaults off in `find_toy`. Waiting, including past `max_dwell_sec`, leaves the index unchanged. No source name `TimeOut`, `AddAutoEndTimer` or `InitTimerBar`.
5. **The prompt is a voice key:** the def field matches `Ids.PATTERN` and is resolved by the existing key resolver. It is not a file path.
6. **One playable Care scene:** `find_toy.tres` runs on the player. Every target is at least 120 px at both aspects. The template knows no room.

## 4. Zoom-Out on the Modules This Touches

**`Tap` (e13s02)** — purpose: answer a touch in `any`, `count_n` and `toggle`, on `TapButton`, with the `device == -1` echo filter.

- Callers: `t21_touch_each`, `t0_title`, `t32_reward`, `t51_prize_pick`, and now Sequence / `t55_find`.
- Contracts to preserve: three modes only; a spent target still answers; no auto-end timer inside Tap; `TapButton` stays the only tap surface.

## 5. Frozen Contracts

### The order is data

The sequence, the indicator and the voice key live in the def. The modifier holds no table of toys.

### A wrong tap still answers

Progress stays put. The sound still plays in the same frame. A silent control teaches a child that touching stopped working.

### Time on screen is not an ending

If the def shows elapsed time, the number is decoration. Completion has one cause: the last id in the order.

## 8. Out of Scope

## 9. Risks

- **A timer that ends the step** returns `AddAutoEndTimer` under another name. Mitigation: the test advances past the dwell and past a shown elapsed time and asserts the index is unchanged.
- **Sequence becoming a Tap mode** would reopen e13s02. Mitigation: the mode set is asserted unchanged, and the modifier is a separate script.
- **A voice field that is a file path** would break the id contract from e12. Mitigation: the field is checked with `Ids.PATTERN` before the resolver runs.
