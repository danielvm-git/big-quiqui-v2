## 1. Story Goal

Two coloring templates, each proven by a step of one Care scene. `t44_paint` deposits a palette color
by rubbing. `t43_color_fill` fills a named area by giving it a color. The photo gallery that ships
with every TutoTOONS color-fill scene stays declined.

## 2. Requirements

#### ADDED: t44_paint
**After:** A palette of tools from the step def. Tapping a chip sets the active color and reports no progress. Rubbing uses the existing Rub `leave` mode and deposits that color. Coverage ratio comes from Rub. The completion threshold is a def value. The template knows no room.

#### ADDED: t43_color_fill
**After:** Each area names the color it accepts. The child gives that color with the existing Give→Receive `pick_one` mode. A matching drop fills the area. A miss returns the chip to the tray with a soft sound and changes nothing. The step completes when every area is filled.

#### ADDED: Adaptation rule for t44_paint
**After:** Deposit color is Rub `leave` plus a def color on the tool. It is not a new Rub mode. `clear`, `leave` and `reveal` stay the three modes e13s01 shipped. `cut` stays with `t42_slice_cut` in e16. Chip labels are pictures. One loop channel stays inside `ScrubGesture`. `t40_draw_fill` is a different template and is not edited: t40 covers one layer, t44 paints with a palette.

#### ADDED: Adaptation rule for t43_color_fill
**After:** Fill is Give→Receive `pick_one` with a color id on the chip and on the area. It is not a new Give mode. `single`, `pick_one` and `slots` stay the three modes e12s04 shipped. The gallery verbs do not return.

#### REMOVED: PhotoGallery on color fill
**Before:** Every TutoTOONS `t43` scene carries `PhotoGallery` (`TakePhoto`, `SaveToFile`, `LoadPhotos`, `DisplayPhotos`), and `t25_map` exposes `ShowOrHidePhotoGallery`.
**After:** (removed) — the gallery verbs do not return. No `TakePhoto`, no `SaveToFile`, no `LoadPhotos`, no `DisplayPhotos`, no `ShowOrHidePhotoGallery`, and no `PhotoGallery` type. The template writes no screenshot and no file. The fill is the whole template.

#### ADDED: The coloring scene
**After:** `res://data/scenes/coloring.tres` is a Care play scene on the player. Step one names `t44_paint`. Step two names `t43_color_fill`. The id `coloring` is in `SceneCatalog` and is an unlocked map destination. It is not a CareLoopManager step.

## 3. Acceptance Criteria

1. **Strict Typing & Lint:** fully annotated; lint/format pass; no file over 300 lines, no function over 20.
2. **`t44_paint` deposits through Rub `leave`:** the palette and the active color come from the def; a chip tap changes the color and does not advance the step; progress is the covered-area ratio; the step completes at the def threshold and stays complete.
3. **`t43_color_fill` fills through Give `pick_one`:** a matching color fills the area in the same frame; a wrong color returns to the tray; the step completes when every area is filled, once.
4. **The gallery verbs do not return:** a source scan of the template fails if it contains `TakePhoto`, `SaveToFile`, `LoadPhotos`, `DisplayPhotos`, `ShowOrHidePhotoGallery` or `PhotoGallery`. No def key can switch a capture on.
5. **No new gesture mode:** Rub stays `clear` / `leave` / `reveal`. Give stays `single` / `pick_one` / `slots`. `touch_draggable.gd` and `scrub_gesture.gd` do not grow.
6. **One playable Care scene uses both:** `coloring.tres` runs on `res://scenes/scene_player.tscn`. No new `.tscn`. Targets are at least 120 px at `1920×1080` and `2048×1536`.

**`Give→Receive` (e12s04)** — purpose: drag an item to a receiver in `single`, `pick_one` and `slots`.

- Callers: `t20_drag_snap`, `t45_dress_decorate`, and now `t43_color_fill`.
- Contracts to preserve: three modes only; a miss returns the item and changes nothing; `touch_draggable.gd` stays at its grandfathered size; a def names ids, never a script path.

## 5. Frozen Contracts

### The gallery verbs do not return

`TakePhoto`, `SaveToFile`, `LoadPhotos`, `DisplayPhotos`, `ShowOrHidePhotoGallery` and `PhotoGallery` have no counterpart in `t43_color_fill` and no def key. Color fill ends at the filled area.

### Two templates, no room nouns

`brush`, `chip` and `area` are def values. Neither template learns the scene id `coloring`.

### A finished coloring step stays finished

Later rubbing or another drop does not un-complete the step and does not write a file.

## 9. Risks

- **A fourth Rub mode named `color`** would reopen e13s01. Mitigation: the test asserts the mode set is still the original three, and the color is def data on `leave`.
- **A gallery verb returning beside the fill** would write a file from a care scene. Mitigation: `SC-e15s01-P0-04` scans the template source and fails if any of the six names is present. Security for this path is `medium`, from the e13 threat-model row that names e15. Agent C writes e15's threat model; this story does not.
- **Paint and draw-fill becoming one template** would erase the palette. Mitigation: `t40` is not edited, and `t44` keeps a palette in the def.
