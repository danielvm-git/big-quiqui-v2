# e07s03: Safe detour auto-completion guard — opening a detour mid-celebration never bricks the Casa

<!-- story: e07s03 -->
- **Epic:** `e07-sleep-and-celebration-scenes`
- **BCP:** 2
- **Playable Vertical Target:** `res://scenes/quarto_sono.tscn` + `res://scenes/celebracao.tscn`
- **Threat findings closed here:** T-E07-05 (detour mid-CELEBRATE)

## 1. Story Goal
A child can wander off from CELEBRATE (to the album, the vila, or home) without the care cycle
getting stuck: the loop auto-completes to IDLE after a detour, and the next Casa visit starts a fresh
cycle instead of refusing every step.

## 2. Acceptance Criteria
1. **Strict Typing & Lint:** `gdlint game/ && gdformat --check game/` exits `0`, type gate passes.
2. **Touch & Mouse-Echo Safety:** every interactive node filters `device == -1`; one tap or drag is one action.
3. **Observability & Traceability:** `logs.sh audit --self-test` and `trace-stories.sh --strict` exit `0`.
1. Leaving `CELEBRATE` through any door other than the Casa arm auto-closes the cycle to `IDLE` within one frame, so the hub is never bricked.
2. The guard is a single function on `CareLoopManager` (`close_celebrate_if_needed()`), not a flag cluster in each scene.
3. A second call is a no-op (idempotent); `FsmProbe` stays clean across the detour.
4. The reward is still paid exactly once — the guard does not re-enter `complete_cycle`.
5. The hub after a detour reports `IDLE` and the first care door is available again.

## 3. Frozen Contract
`CareLoopManager.close_celebrate_if_needed() -> bool` — returns true when it closed the cycle.
Called by `SceneManager` on any scene request made while the loop is in `CELEBRATE` and the target is not
the Casa.

## 4. Test Scenarios
- `SC-E07-P0-12 a detour during CELEBRATE returns the loop to IDLE`
- `SC-E07-P0-13 the guard is idempotent and pays nothing`
- `SC-E07-P1-14 the hub is usable immediately after the detour`
